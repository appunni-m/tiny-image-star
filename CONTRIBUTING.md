# Contributing to Tiny Image Star

Tiny Image Star welcomes focused bug fixes, accessibility improvements,
documentation corrections, deterministic tests, and changes that preserve its
private, browser-only model.

The application is pre-release. Open an issue before a large product or
architecture change so effort is not spent against an obsolete direction.
Security reports must follow [SECURITY.md](SECURITY.md), not a public issue.

## Set up a clean checkout

Prerequisites:

- Node.js 20 or newer;
- npm, using the committed `package-lock.json`;
- Python 3 or another static HTTP server for manual browser checks.

```bash
npm ci
npx playwright install chromium
npm run verify:all
```

Success means both the deterministic byte checks and browser smoke complete
with exit code 0. Linux CI installs Chromium's system dependencies with
`npx playwright install --with-deps chromium`; most local systems need only the
command shown above.

## Work locally

Serve the repository instead of opening `index.html` directly:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

Then open <http://127.0.0.1:8000/>. A random port can be selected by replacing
`8000` with `0`.

Use `npm run verify:watch` for fast checks while editing. Run
`npm run verify:all` before submitting a change. The complete feature-to-test
contract is in [VERIFICATION_MATRIX.md](VERIFICATION_MATRIX.md).

## Repository map

| Path | Responsibility |
| --- | --- |
| `src/editor/` | Canvas state, direct interactions, rendering, and editor processing. |
| `src/batch.js` | Shared image-set workflow, result selection, overrides, and saves. |
| `src/jobs/` | Durable, bounded-memory large-folder jobs. |
| `src/engine/pillow.js` | App-owned adapter around the generated image engine. |
| `src/worker.js` | Interactive image processing off the main thread. |
| `scripts/verify.mjs` | Fast deterministic byte/state contract. |
| `scripts/browser-smoke.mjs` | Headless browser interaction and output checks. |
| `wasm/` | Generated Pillow-RS JavaScript/WASM runtime and its notice. |

The application modules are internal implementation, not a published JavaScript
library API. Exported functions exist to keep modules testable and composable;
they do not currently carry semantic-versioning compatibility promises.

## Change rules

- Keep visible product language non-technical. Implementation terminology
  belongs in contributor documentation and diagnostics.
- Preserve local-only processing. Do not add accounts, uploads, analytics,
  remote fonts, or cloud-only features without an explicit product decision.
- Never expose a format or quality choice until generated bytes pass real
  signature/decode/transform checks.
- Keep editor and image-set behavior unified. A one-image import is the
  one-item form of the same workflow.
- Do not edit the Pillow-RS checkout from this repository. Record dependency
  gaps in `PILLOW_RS_ISSUES.md`.
- Do not add private/user images as fixtures. Use small generated or
  redistributable fixtures and document their origin.
- Preserve unrelated work and keep changes narrowly reviewable.

## Generated image-engine files

`wasm/pillow_rs_js.js` and `wasm/pillow_rs_js_bg.wasm` are generated together
and must never be hand-edited independently. A change that replaces them must:

1. identify the exact Pillow-RS source revision and build command;
2. update `wasm/README.md` with new checksums and provenance;
3. retain the upstream license text; and
4. pass `npm run verify:all` before the artifact is committed.

The current artifact predates a recorded source revision. That known provenance
debt is stated in `wasm/README.md`; do not invent a revision for it.

## Pull requests

Keep the title and description user-focused. Include:

- the problem and intended user-visible outcome;
- screenshots or a short recording for layout/interaction changes, with
  private data removed;
- commands run and their exit status;
- added or changed deterministic coverage;
- browser/platform boundaries that were not exercised; and
- any change to local storage, permissions, memory limits, or output bytes.

There is currently no CLA or DCO sign-off requirement. Contribution licensing
cannot be finalized until the project owner selects the repository license;
see the README's license status before submitting reusable code.
