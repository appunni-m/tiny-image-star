# Tiny Image Star

Tiny Image Star is a local-first visual design editor. It provides pages and nested layers, a canvas workspace with layer and property panels, and a responsive mobile layout with slide-in side panels. Design documents and image sources stay in the current browser profile on this device.

The editor supports editable vector paths and graph-backed Pen networks with shared junctions, branching strokes, closed fill regions with independent color and opacity, per-edge Bézier handles, curve-preserving point insertion, and topology-aware point deletion. Networks can be used as live Boolean operands and alpha masks. Other features include layer grouping and ungrouping, bounds-aware multi-selection alignment and distribution, shared resize and rotation handles for multi-selected layers through rotated parents, copy/cut/paste/duplicate layer actions with undo and redo, live non-destructive Boolean groups, editable alpha-mask groups, solid, linear, and radial fills with editable color stops, clipped image fills with Fill/Fit scaling and local Pillow-RS adjustments, 16 layer blend modes, drop shadows and layer blur, and text boxes with fixed-size, auto-height, and auto-width behavior, editable system font families, the 100–900 weight scale, italic styling, text case, vertical alignment, and underline or strikethrough. Text can be selected and formatted inline with bold, italic, font family, weight, size, letter spacing, decoration, and color controls; mixed run styles affect layout, rendering, and SVG export. Reusable text styles snapshot font family, size, weight, style, line height, letter spacing, horizontal and vertical alignment, color, case, and decoration; they can be applied to selected text or updated for future use. The editor also supports selection and transforms, multi-select, horizontal and vertical auto layout, grid auto layout with independent row and column gaps, manual cell placement and spans, per-layer minimum and maximum sizing in auto layout, responsive frame constraints, frame layout guides, and an outline view. The Inspect panel shows resolved layer values and provides copyable nested HTML scaffolding, CSS, and exact local layer JSON. It also supports linked components, instances and variant sets, reusable color styles, and typed variables with per-mode aliases and frame-level theme overrides. Variable bindings can drive paint, text, typography, opacity, radius, visibility, and Auto Layout direction, alignment, distribution, spacing, padding, grid counts, and wrap behavior. Images use local Pillow-RS WebAssembly for brightness, contrast, saturation, sharpness, blur, crop, and quarter-turn rotation, with each render starting from the original image held in memory so edits do not compound; those settings stay editable after reload and are captured in image recipes. Image fills reference those same local image sources and remain editable after reload or `.flocal` export. Saved image recipes can be applied to a multi-selection from the canvas or Layers panel using an in-place batch bar with pause, cancel, progress, and worker controls. Local design files can be imported and exported as `.flocal` packages. SVG imports convert supported vector primitives, paths, and simple text runs into editable layers inside an editable frame; unsupported geometry, text semantics, paint, and unsafe content are rejected rather than flattened silently. SVG export preserves editable vector shapes and text, emits graph-backed networks as editable paths, embeds local raster layers and unadjusted image fills, and supports simple vector alpha-mask groups plus solid, linear, and radial shape fills, drop shadows, layer blur, and blend modes. Unsupported SVG export content—including adjusted or transformed raster images, Boolean layers, text or open-vector mask sources, blended mask sources, and unsupported gradient placements—is rejected with a specific message.

Component slots turn a nested frame, group, or section in a main component into a replaceable content area. On an instance, Choose content or Replace opens a searchable picker of layers on the current page; applying copies the selected layer trees into the slot and leaves their originals in place. Reset restores the component's default slot content. Custom slot content is local to each instance, survives component sync, save/reload, and detach, and carries across variant changes when the destination variant has a slot with the same name.

SVG import is local and converts supported primitives and single-subpath vector paths into editable path layers, preserving groups, solid paints, supported gradients, transforms, and viewBox sizing. It also imports a single plain text run into a native text layer when the baseline and styling map directly to editor controls; simple font family, size, weight, style, anchor, letter spacing, decoration, case, and positive uniform scale/rotation are retained. It rejects scripts, event handlers, linked images, external references, CSS classes, filters, masks, compound paths, even-odd fills, `<tspan>` runs, per-character positions, unsupported baselines or paint, and unsupported transforms rather than silently flattening or dropping them. SVG text imports require `dominant-baseline="text-before-edge"`; other baseline metrics depend on the source font and cannot be represented exactly by the native text layer.

Layer order can be changed by dragging rows or by the touch-sized up/down controls on a selected row; both operations support undo and redo. Prototype interactions can be guarded by typed variable equality or inequality conditions, evaluated against the active presentation mode and the layer's resolved frame mode. On phones, closed side panels leave keyboard and screen-reader navigation, opening moves focus into the panel, and dismissing restores focus to its toggle.

Image processing and memory: Pillow-RS workers decode and transform image pixels; the browser Canvas2D renderer draws the resulting previews and composites them with vector, text, and other layers. Before creating a browser bitmap, image import and restore inspect the header and reject sources above the 80-million-pixel limit. The preflight currently recognizes PNG, JPEG, GIF, BMP, WebP, and PNM headers and scans at most 1 MiB; unknown or unusually long headers fail closed because compressed file size cannot safely predict decoded memory. The worker pool starts at up to two workers, and the batch speed control can raise the requested maximum to the detected CPU count (falling back to four when unavailable), capped at eight. Actual active workers can be lower when image size approaches the memory budget; the batch bar shows the requested maximum and current active workers. The retained decoded-source cache uses a device-tiered 4/8/16-million-pixel budget shared across active workers. A second admission budget estimates transient WASM render memory from common image headers at 32 bytes per pixel, with a 192–1024 MiB device tier (256 MiB when device memory is unknown); unrecognized formats reserve the full 80-million-pixel estimate and run alone. This estimate covers active WASM renders, not total browser memory; original bytes, browser bitmaps, previews, and output buffers also consume memory, so large designs can still be constrained by available device memory.

Prototype interactions can connect layers to frames with click/tap, hover, or after-delay triggers; after-delay waits are configurable from 100 ms to 10 seconds and are canceled when presentation navigation changes the active frame or the presentation closes. Flows can set a starting point, configure transitions including Smart Animate with linear, ease-in, ease-out, or ease-in-out timing, open or swap centered or edge-positioned overlays, open validated web and mail links, go back through navigation history, set a variable collection's mode for the active presentation, dim the presentation background, and dismiss overlays from their own interactions or outside clicks. Smart Animate matches layers by name and parent hierarchy, interpolates geometry and rotation along the shortest arc, opacity, numeric text metrics, compatible solid colors, and compatible drop-shadow and layer-blur effect stacks. Categorical text and paint styles switch at the midpoint. Compatible unbound gradients of the same type and stop count interpolate their angle, stop positions, and colors; variable-bound or incompatible gradients switch at the midpoint. Compatible vector paths with the same open/closed state and point count morph their anchors and Bézier handles. Compatible vector networks with unchanged vertex/edge/face topology morph their vertices and Bézier controls; incompatible paths and networks crossfade. These links are stored with the local document.

Canvas comments support anchored review threads, replies, resolution, and deletion. Threads are saved inside the local design file and included in `.flocal` exports; they do not sync between devices.

This is an active rebuild, not production certification or complete parity with mature collaborative design tools. Boolean previews use a bounded-resolution local canvas composite while keeping their source vectors editable. Linked component instances retain local property, geometry, and child-order overrides while main component structure and styling synchronize. Component sets support named variant properties, per-instance variant switching, and override migration across structurally matching layers. Main components support reusable Boolean visibility, text, and nested instance-swap properties; linked instances expose those values in the Inspector. Component slots expose nested frames, groups, and sections as replaceable instance content. Further work remains on advanced vector operations, richer text and layout controls, wider Smart Animate parity, cross-device comment sync and multiplayer, framework-specific developer handoff, and proprietary design-file import. SVG exports network faces and edges as ordinary paths, so graph editing semantics do not survive. SVG alpha masks support rectangle, ellipse, star, and polygon sources, closed paths, and networks with closed regions. Mask sources that are text, open paths or networks, Boolean layers, or blended layers remain unsupported; Boolean layers and adjusted or transformed raster images are also unsupported in SVG exports. Tiny Image Star does not claim compatibility with third-party project files or cloud services.

## Design tokens and prototype gestures

The Variables panel imports and exports DTCG token JSON on this device. Standard DTCG input supports color, number, and string tokens with aliases. Tiny Image Star exports those values as regular DTCG tokens and includes a local extension to round-trip every collection and mode; other DTCG tools see each collection's default mode. Boolean variables export as strings because DTCG has no boolean token type. Unsupported types, alpha colors, and color precision the editor cannot retain are rejected rather than silently changed.

Prototype links also support on-press and on-drag triggers, plus component-instance variant changes such as hover states. Press fires on pointer-down; drag requires movement. Variant changes affect only the local presentation session and leave the saved design unchanged.

## Run locally

```sh
npm run dev
```

Open `http://127.0.0.1:8000`. The app does not upload image or design data. The local server sends cross-origin isolation headers needed by WebAssembly workers.

## Verify

```sh
npm test
npm run verify:static
```

With the server running, open `http://127.0.0.1:8000/tests/browser-smoke.html` to run the browser workflow smoke. It exercises image previews and recipes, sharpness and image-fill editing, portable reload, layer blend-mode rendering, text fonts and reusable styles, local packages, components and variants, vector editing, grouping and alignment, variables and conditional prototype interactions, grid auto layout, Boolean operations, gradients and layer effects, prototype presentation, masks, and mobile Layers touch targets. Open `http://127.0.0.1:8000/tests/layer-order-smoke.html` to verify drag ordering, phone-sized row controls, lock/boundary behavior, undo/redo, and persistence. Open `http://127.0.0.1:8000/tests/mobile-recipe-smoke.html` to verify saving a cropped and rotated recipe from one image and applying it to a touch-selected batch without keyboard modifiers or context menus, including reachable live speed and pause controls plus phone-panel accessibility. Open `http://127.0.0.1:8000/tests/bulk-recipe-scale-smoke.html` to stress a 48-image recipe batch, live worker-count changes, pause/resume, in-place results, and cancellation cleanup. Open `http://127.0.0.1:8000/tests/svg-import-smoke.html` to verify mobile-sized SVG file picking, editable layer import, repeat-import ID uniqueness, and atomic rejection of active or external content. Open `http://127.0.0.1:8000/tests/editor-parity-smoke.html` to verify local design open, duplicate, rename and delete, plus nested and multi-layer resize and rotation gestures. Open `http://127.0.0.1:8000/tests/mask-smoke.html` to verify editable mask creation and release through the Layers context menu and Layer options menu, `http://127.0.0.1:8000/tests/export-smoke.html` to verify mobile-ready raster settings plus selected-layer and page SVG downloads, `http://127.0.0.1:8000/tests/guides-smoke.html` to verify frame guides and mobile controls, `http://127.0.0.1:8000/tests/outline-smoke.html` to verify outline mode, `http://127.0.0.1:8000/tests/inspect-smoke.html` to verify text sizing, case and decoration controls, editable gradients and effects, nested HTML/CSS and JSON handoff, clipboard actions, and phone-sized controls, or `http://127.0.0.1:8000/tests/comments-smoke.html` to verify canvas comments, replies, resolution, local persistence, and phone controls.
