# Tiny Image Star

Tiny Image Star is a local-first visual design editor. It provides pages and nested layers, a canvas workspace with layer and property panels, and a responsive mobile layout with slide-in side panels. Design documents and image sources stay in the current browser profile on this device. A local version history keeps a bounded rolling set of document snapshots and lets you name and restore milestones without uploading design data. Share packages the active design, its embedded images, and its used local fonts into a portable `.flocal` file up to 128 MiB; supported devices open their system share sheet, while other browsers download the file. Oversized packages are rejected before their image and font bytes are loaded or a selected import file is read into memory.

Local font files in WOFF2, WOFF, TTF, or OTF format can be added from the Assets panel. Tiny Image Star checks the file signature and size, then asks the browser's `FontFace` loader to decode the file before storing it on this device. Set its family, weight, and regular or italic style during import. Installed font faces appear in text-family pickers and load again with the local design library. Fonts used by a design are included in its `.flocal` export and restored on import; a same-family face collision is given a distinct imported family so existing designs keep their original font. System fonts and freeform family names continue to work.

Image layers and image fills can use local Pillow-RS auto-contrast, posterize, solarize, and invert. PNG transparency is preserved, previews are rendered from the original pixels held in memory, and the controls are saved with image recipes for later single-image or bulk application. Recipes also capture PNG, JPEG, or WebP output plus quality; applying one stores those options on each target image for later export. The working preview stays lossless PNG. “Download edited original” runs the image’s crop, rotation, and adjustments from the retained source at its transformed source resolution. PNG uses Pillow-RS output; JPEG and WebP are encoded locally by the browser so the saved quality value is honored. Layer export settings and canvas selections keep their existing scene-sized exports.

The editor supports editable vector paths and graph-backed Pen networks with shared junctions, branching strokes, closed fill regions with independent color and opacity, per-edge Bézier handles, curve-preserving point insertion, topology-aware point deletion, and a contour-direction control that preserves curve geometry. Networks can be used as live Boolean operands and alpha masks. Other features include layer grouping and ungrouping, bounds-aware multi-selection alignment and distribution, shared resize and rotation handles for multi-selected layers through rotated parents, copy/cut/paste/duplicate layer actions with undo and redo, live non-destructive Boolean groups with editable shape and text sources, including variable-mode-resolved content and typography, baking supported Boolean results into editable compound vector paths, and editable alpha-mask groups; baking supports square-corner rectangles, polygons, stars, straight closed paths, and cubic Bézier paths with transversal, numerically isolated intersections, and refuses unsupported geometry with an explanation. The editor also supports independent per-corner radii on rectangles, frames, sections, and image layers, solid, linear, and radial fills with editable color stops, clipped image fills with Fill/Fit scaling and local Pillow-RS adjustments, 16 layer blend modes, drop shadows, inner shadows, and layer blur, and text boxes with fixed-size, auto-height, and auto-width behavior, editable system font families, the 100–900 weight scale, italic styling, line height, paragraph spacing, first-line indentation, per-paragraph alignment and lists, text case, vertical alignment, and underline or strikethrough. Paragraph spacing and first-line indentation affect wrapping, auto-sizing, canvas rendering, reusable text styles, SVG export, and the Inspect HTML/React/Vue and CSS handoff. Text can be selected and formatted inline with bold, italic, font family, weight, size, letter spacing, decoration, and color controls; mixed run styles affect layout, rendering, and SVG export. Reusable text styles snapshot font family, size, weight, style, line height, letter spacing, paragraph spacing, first-line indentation, horizontal and vertical alignment, color, case, and decoration; they can be applied to selected text or updated for future use. The editor also supports selection and transforms, multi-select, horizontal and vertical auto layout, grid auto layout with independent row and column gaps, manual cell placement and spans, per-layer minimum and maximum sizing in auto layout, responsive frame constraints, frame layout guides, an outline view, and review-before-apply auto-layout suggestions for clear rows, columns, and complete grids. The Inspect panel shows resolved layer values and provides copyable nested HTML scaffolding, CSS, React JSX, Vue 3 single-file component scaffolding, and exact local layer JSON. Layers also support ordered stacks of up to 32 independently editable solid strokes, with per-stroke color, width, opacity, visibility, cap, join, dash pattern, and miter limit; the Canvas and SVG render in order, compatible stacks interpolate in Smart Animate, and Inspect JSON preserves the complete stack. Text wrapping uses grapheme-safe fallback, CJK punctuation-aware breaks, and Thai dictionary boundaries when `Intl.Segmenter` is available; long unbroken tokens wrap without compressing the whole line. The framework scaffolds are adaptable starting points: app-specific local image sources and vector/mask rendering must be connected in the destination app. Inspect also supports linked components, instances and variant sets; the Assets panel can edit set names, axes, and per-variant values and place an exactly selected variant. It also supports reusable color styles and typed variables with per-mode aliases and frame-level theme overrides. Variable bindings can drive paint, text, typography, opacity, radius, visibility, and Auto Layout direction, alignment, distribution, spacing, padding, grid counts, and wrap behavior. Images use local Pillow-RS WebAssembly for brightness, contrast, saturation, sharpness, blur, crop, and quarter-turn rotation, with each render starting from the original image held in memory so edits do not compound; those settings stay editable after reload and are captured in image recipes. Image fills reference those same local image sources and remain editable after reload or `.flocal` export. Saved image recipes can be applied to a multi-selection from the canvas or Layers panel using an in-place batch bar with live pause, cancel, progress, worker controls, pause-aware images-per-second and ETA, and a retry action for failed images. On phones, Layers Select toggles any layer type without modifier keys; recipes still apply only to selected images. Local design files can be imported and exported as `.flocal` packages. SVG imports convert supported vector primitives, paths, graph metadata and styled rich text runs into editable layers inside an editable frame; unsupported geometry, paint, and unsafe content are rejected rather than flattened silently. SVG export preserves editable vector shapes, network topology, and text, embeds local raster layers and unadjusted image fills, and supports vector alpha-mask groups, Boolean union/subtract/intersect/exclude, crop and quarter-turn image transforms, solid/linear/radial shape fills, shadows, blur, and blend modes. Exclude operations preserve their vector operands and use alpha-correct SVG XOR filter composition. Edited images are embedded from local PNG previews. SVG still rejects unsupported Boolean blending, text or open-vector mask sources, and unsupported gradient placements; importing foreign SVG paths does not invent graph editing topology.

Component slots turn a nested frame, group, or section in a main component into a replaceable content area. On an instance, Choose content or Replace opens a searchable picker of layers on the current page; applying copies the selected layer trees into the slot and leaves their originals in place. Reset restores the component's default slot content. Custom slot content is local to each instance, survives component sync, save/reload, and detach, and carries across variant changes when the destination variant has a slot with the same name.

Component sets can be managed in Assets: rename the set, add or rename variant axes, edit each variant’s axis values, and remove an axis only when the remaining axes still distinguish every variant. Assets provides a persistent variant chooser and per-variant Place controls so the chosen master is instantiated exactly. New axes start with a shared value that can be customized per variant. Variant sets are still formed from existing main components; the editor does not generate a missing design variant from scratch.

Auto-layout suggestions analyze direct visible children of a selected frame and preview inferred horizontal rows, vertical columns, or complete regular grids. Review the inferred settings before applying; stale suggestions and changes that would move or resize a child beyond tolerance are rejected. Uncertain visible layers remain in absolute positioning, and analysis is capped at 2,048 children. See [Auto-layout suggestions](docs/auto-layout-suggestions.md) for the supported patterns and limits.

Local component libraries are shared across designs in the same browser profile and stay on this device. Publish a main component from the Assets panel, place linked instances in another design, and publish edits as new revisions. Existing instances can update to a newer revision while keeping compatible local overrides and their canvas placement; detaching leaves the layer tree editable in that design.

SVG import is local and converts supported primitives and compound vector paths into editable path layers, preserving each contour's closure, nonzero or even-odd fill rules, groups, solid paints, supported gradients, transforms, and viewBox sizing. Compound contours share one path box and remain independently editable. It imports plain text and ordered nested `<tspan>` runs into native rich-text layers, preserving supported per-run font family, size, weight, style, line height, letter spacing, decoration, and solid color. Text anchors, simple text styling, and positive uniform scale/rotation are retained. Scripts, event handlers, linked images, external references, CSS classes, filters, per-character positioning, unsupported text opacity or paint, unsupported baselines, and unsupported transforms are rejected rather than silently flattened or dropped. Text import requires `dominant-baseline="text-before-edge"`; other baseline metrics depend on the source font and cannot be represented exactly by the native text layer.

Layer order can be changed by dragging rows or by the touch-sized up/down controls on a selected row; both operations support undo and redo. Each layer row also has a keyboard-accessible actions menu with touch-sized controls on phones. Prototype interactions can be guarded by typed variable equality or inequality conditions, evaluated against the active presentation mode and the layer's resolved frame mode. On phones, closed side panels leave keyboard and screen-reader navigation, opening moves focus into the panel, and dismissing restores focus to its toggle.

Image processing and memory: Pillow-RS workers decode and transform image pixels; the browser Canvas2D renderer draws the resulting previews and composites them with vector, text, and other layers. The vendored WASM runtime is built from Pillow-RS `12.2.0-alpha.2` at upstream commit [`533de86`](https://github.com/appunni-m/pillow-rs/commit/533de8607e2d246e1d166f029abd08b7c73191f3). This pre-release is prepared on upstream `main` but is not yet published; `wasm/runtime.json` records the source commit, package integrity, and local file hashes. Pillow-RS documents [operation- and mode-specific limitations](https://appunni-m.github.io/pillow-rs/compatibility/) and warns that alpha APIs may break. Tiny Image Star therefore relies only on locally tested operations and must rerun its WASM regression suite before changing the pinned runtime. Before creating a browser bitmap, image import and restore inspect the header and reject sources above the 80-million-pixel limit. The preflight currently recognizes PNG, JPEG, GIF, BMP, WebP, and PNM headers and scans at most 1 MiB; unknown or unusually long headers fail closed because compressed file size cannot safely predict decoded memory. The editor also accounts for retained source bytes, fallback bitmaps, rendered previews, pending decodes, and preview replacement reservations under a device-tiered 96–384 MiB budget (160 MiB when device memory is unavailable). The worker pool starts at up to two workers, and the batch speed control can raise the requested maximum to the detected CPU count (falling back to four when unavailable), capped at eight. Actual active workers can be lower when image size approaches the render budget; the batch bar shows the requested maximum and current active workers. Concurrent Pillow-RS jobs share a 192/320/640/1024 MiB device tier (256 MiB when device memory is unknown), with a separate per-image hard ceiling of 192 MiB on devices up to 2 GiB, 320 MiB up to 4 GiB, and 512 MiB otherwise. The estimate uses 32 bytes per source pixel for WASM and encoder working memory; unknown headers receive the full 80-million-pixel estimate and are rejected by the per-image ceiling. These estimates do not measure all browser memory, so large designs can still be constrained by available device memory. When a single image layer or image fill is selected, its decoded Pillow-RS source is kept in the worker cache while it fits the existing budget; selection changes release that priority, and larger sources still re-decode from retained original bytes.

Prototype interactions can connect layers to frames with click/tap, hover, or after-delay triggers; after-delay waits are configurable from 100 ms to 10 seconds and are canceled when presentation navigation changes the active frame or the presentation closes. Flows can set a starting point, configure transitions including Smart Animate with linear, ease-in, ease-out, or ease-in-out timing, open or swap centered or edge-positioned overlays, open validated web and mail links, go back through navigation history, set a variable collection's mode for the active presentation, dim the presentation background, and dismiss overlays from their own interactions or outside clicks. Smart Animate matches layers by name and parent hierarchy, interpolates geometry and rotation along the shortest arc, opacity, numeric text metrics, compatible solid colors, and compatible drop-shadow and layer-blur effect stacks. Categorical text and paint styles switch at the midpoint; matched text layers keep their interpolated geometry while their content changes at the midpoint. Compatible unbound gradients of the same type and stop count interpolate their angle, stop positions, and colors; variable-bound or incompatible gradients switch at the midpoint. Compatible vector paths with the same contour count and matching per-contour closure and point counts morph all anchors and Bézier handles. Compatible vector networks with unchanged vertex/edge/face topology morph their vertices and Bézier controls; incompatible paths and networks crossfade. These links are stored with the local document.

Canvas comments support anchored review threads, replies, resolution, and deletion. Threads are saved inside the local design file and included in `.flocal` exports; they do not sync between devices.

This is an active rebuild, not production certification or complete parity with mature collaborative design tools. Boolean previews use a bounded-resolution local canvas composite while keeping their source vectors and text editable, and resizing scales source geometry into the group bounds. Baking supported Boolean results creates native compound paths and preserves supported cubic Bézier handles; square-corner rectangles, polygons, stars, and closed paths are supported when intersections are transversal and numerically isolated. Ellipses, rounded rectangles, vector networks, transparency, blending, mode-bound geometry, component content, tangent or ambiguous intersections, and inputs above explicit complexity limits remain unsupported. Linked component instances retain local property, geometry, and child-order overrides while main component structure and styling synchronize. Component sets support named variant properties, per-instance variant switching, and override migration across structurally matching layers. Main components support reusable Boolean visibility, text, and nested instance-swap properties; linked instances expose those values in the Inspector. Component slots expose nested frames, groups, and sections as replaceable instance content. Inspect provides adaptable React JSX and Vue 3 single-file component scaffolds alongside HTML, CSS, and exact layer JSON; app-specific image and vector rendering still needs to be connected in the destination project. Further work remains on advanced vector operations, richer typography and layout controls, wider Smart Animate parity, cross-device comment sync and multiplayer, and proprietary design-file import. SVG editable alpha-mask groups support rectangle, ellipse, star, polygon, closed paths, and networks with closed regions; Boolean alpha masks also preserve text glyphs and their resolved variable-mode content and typography. Editable mask-group sources that are text, open paths or networks, Boolean layers, or blended layers remain unsupported; Boolean operands with non-normal blend modes, raster adjustments without an available rendered preview, and unsupported gradient placements are not represented. Boolean unions, subtraction, intersection, and exclude export their editable vector and text operands through SVG alpha masks and apply the same source-bounds resize transform as the canvas; exclude combines sequential operands with alpha-correct XOR filters. Crop and quarter-turn rotation export directly from the local source raster, while edited images embed the current local PNG preview. Tiny Image Star does not claim compatibility with third-party project files or cloud services.

## Design tokens and prototype gestures

The Variables panel imports and exports DTCG token JSON on this device. Standard DTCG input supports color, number, and string tokens with aliases. Tiny Image Star exports those values as regular DTCG tokens and includes a local extension to round-trip every collection and mode; other DTCG tools see each collection's default mode. Boolean variables export as strings because DTCG has no boolean token type. Unsupported types, alpha colors, and color precision the editor cannot retain are rejected rather than silently changed.

Prototype links also support on-press and on-drag triggers, plus component-instance variant changes such as hover states. Press fires on pointer-down; drag requires movement. Variant changes affect only the local presentation session and leave the saved design unchanged.

## Vector editing and alignment

The Polygon and Star tools create editable shapes. Select a polygon to set its side count, or a star to set its point count and inner-radius ratio; values stay in the design and editable SVG export. Vector path anchors can be set to Corner, Smooth, or Symmetric. Smooth anchors keep handles collinear while allowing their lengths to differ; converting an untouched Corner anchor to Smooth infers handles from its neighboring anchors, including at open endpoints and around closed paths. Symmetric anchors mirror handle direction and length. On phones, the anchor control remains reachable in the touch-sized properties panel.

When moving layers, the canvas snaps selection edges and centers to visible peer geometry and draws live magenta alignment guides. Hold Alt while dragging to bypass both alignment and grid snapping for that move.

Compound vector paths keep each contour editable inside one layer. Select a contour by clicking one of its anchors, then add or remove contours, insert and delete anchors, and change that contour's open or closed state in the Vector inspector. Closed contours can use the nonzero or even-odd fill rule; SVG import, canvas fills, image-fill clipping, Boolean operands, masks, Smart Animate, local saves, and SVG export preserve the supported contour geometry.

## Bulk recipe recovery

Before an image recipe batch changes a layer, Tiny Image Star stores a small local recovery record for the recipe, page, and target image layers. If a batch is left open or the browser closes unexpectedly, reopening that design offers two choices: resume the saved recipe across the original targets, or keep the image edits that were already saved. The result bar saves the final document before it clears the recovery record.

## Run locally

```sh
npm run dev
```

Open `http://127.0.0.1:8000`. The app does not upload image or design data. The local server sends cross-origin isolation headers needed by WebAssembly workers.
