# Tiny Image Star

Tiny Image Star is a local-first visual design editor. It provides pages and nested layers, a canvas workspace with layer and property panels, and a responsive mobile layout with slide-in side panels. By default, designs and image sources stay in this browser profile on this device. In supported browsers, you can choose a writable folder workspace; its design and page data and verified local assets are saved under that folder. Appearance can follow the device or be fixed to light or dark in the main menu, and the choice follows this browser profile across tabs. A local version history keeps a bounded rolling set of document snapshots and lets you name and restore milestones without uploading design data. Share packages the active design, its embedded images, and its used local fonts into a portable `.flocal` file up to 128 MiB; supported devices open their system share sheet, while other browsers download the file. Oversized packages are rejected before their image and font bytes are loaded or a selected import file is read into memory. Local Figma Design `.fig` files can also be imported as an experimental, best-effort conversion; a review lists features that will be omitted or simplified before the current design is replaced.

Folder workspaces with per-design and per-page folders, plus host-authoritative live WebRTC sharing, are implemented. Live session setup has no Tiny Image Star signaling server: people exchange fresh offers and answers through a channel they choose, and the host remains the only canonical writer. The owner can navigate a connected design in view-only mode while guests follow the current page and canvas view by default; guest edits are saved locally first and become canonical only after the host's durable ACK. Folder selection depends on browser support, so mobile browsers without a writable directory picker cannot host a canonical folder workspace. The collaboration flow still needs real-device and independent-profile validation, security review, and production limits; it is not yet a production-readiness claim. See the [workspace and live-sharing design](docs/local-folder-sharing-design.md) for the implemented behavior and release gaps.

See the [design-editor parity ledger](docs/design-editor-parity.md) for the current Figma Design feature map, verified implementation evidence, and open parity gaps.

Rectangle and frame strokes support Figma-style **All**, **Top**, **Bottom**, **Left**, **Right**, and **Custom** edge weights. A weight of zero removes that edge. Custom weights remain editable after local save/reload, component overrides, `.fig` import, canvas rendering, hit testing, Inspect output, and SVG export. SVG import retains the rendered edge paths as editable vectors; it does not reconstruct the rectangle's individual-weight control yet.

The Frame tool provides grouped starter presets, and a selected frame can switch to a preset from its Inspector. Resizing keeps unconstrained children in place and applies each child’s saved constraints; auto-layout frames recalculate their contents. **Resize to fit** wraps a selected frame around visible child bounds while preserving their canvas positions; use Option/Alt + Shift + Command/Ctrl + R. Auto-layout frames use Hug contents for the same result. The current preset catalog is curated and does not yet reproduce Figma’s full changing device, Community, and Archive lists. Figma documents frame resizing and Resize to fit in [Frames in Figma Design](https://help.figma.com/hc/en-us/articles/360041539473-Frames-in-Figma-Design).

X, Y, W, and H fields accept live calculations: enter a value, a relative change such as `+100`, `-20`, `*4`, or `/8`, or a percentage such as `50%`. Expressions are parsed locally with bounded arithmetic and never executed as code; multi-selection bounds use the same input behavior.

Local font files in WOFF2, WOFF, TTF, or OTF format can be added from the Assets panel. Tiny Image Star checks the file signature and size, then asks the browser's `FontFace` loader to decode the file before storing it on this device. WOFF2 variable-font ranges are inspected with a bundled local WebAssembly decoder in a worker. Set its family, weight, and regular or italic style during import. Installed font faces appear in text-family pickers and load again with the local design library. Fonts used by a design are included in its `.flocal` export and restored on import; a same-family face collision is given a distinct imported family so existing designs keep their original font. System fonts and freeform family names continue to work.

Local variable fonts in WOFF2, WOFF, TTF, and OTF formats expose their OpenType axis ranges as inspector sliders. OpenType feature controls include common typography switches and custom four-character tags with numeric values. Axis and feature settings persist on text layers and rich-text runs, in saved styles, component overrides, collaboration edits, local saves, Inspect output, and SVG round trips. A pinned local HarfBuzz WebAssembly worker shapes locally installed fonts for canvas preview, text-on-path, and auto-size measurements when its shaped run is available; unsupported glyphs retain browser fallback. Mixed-script fallback itemizes common writing systems into grapheme-safe local-font runs and leaves uncommon scripts on the browser's shaping stack; cold-load and visual fidelity still need browser validation.

Image layers and image fills support Fill (cover), Fit (contain), and Tile (repeat the original source at an editable 1–1600% scale); Tile ignores but preserves any saved crop, and keeps quarter-turn rotation and flips. Image layers and image fills provide local Pillow-RS exposure, temperature, tint, brightness, contrast, highlights, shadows, saturation, sharpness, blur, auto-contrast, posterize, solarize, and invert. PNG transparency is preserved, previews are rendered from the original pixels held in memory, and the controls are saved with image recipes for later single-image or bulk application. Recipes also capture PNG, JPEG, or WebP output plus quality; applying one stores those options on each target image for later export. From an image’s recipe controls, saved recipes can be refreshed from that image, renamed, or deleted; edits to the catalog affect future applications, while existing images keep their current look. The working preview stays lossless PNG. “Download edited original” runs the image’s crop, rotation, horizontal and vertical flips, adjustments, and JPEG/WebP quality through the pinned local Pillow-RS WASM worker at the transformed source resolution. Layer export settings and canvas selections keep their existing scene-sized exports.

Image layers also include local AI object erase. Choose **Brush to erase** in the image Inspector, paint over an object, then choose **Done erasing**; undo and clear remain available, and the original source is retained. A pinned MI-GAN ONNX model runs in a dedicated one-thread WebAssembly worker with no image upload. Only pixels under the erase mask are replaced; surrounding RGB and the original alpha are preserved. Erase marks survive local save/reload and are captured in image recipes, including bulk recipe runs. To bound mobile memory and CPU work, the model accepts source images up to 4,194,304 pixels and serializes its inference jobs; batch speed reserves its shared local-model slot before admitting Pillow-RS render workers. The final preview and exports continue through Pillow-RS.

The image Inspector also provides a local **Expand** operation. It adds selected-side padding to the same image layer, runs the bundled MI-GAN model in the same bounded ONNX/WASM path, restores the original source pixels exactly inside the expanded canvas, and keeps the original size/source available for Undo or restore. Saved recipes retain the source-relative padding ratios and can apply expansion in place to multiple images using each target's own original pixels and geometry. Reapplying the same expansion ratio does not regenerate its borders. This is an unprompted masked-fill model, not semantic prompt editing; model quality and phone performance remain unverified pending the deferred browser and real-device checks. Local prompt-based image generation and prompt-guided edits are not implemented.

The image Inspector also includes a local **Resolution Boost** operation. A pinned Real-ESRGAN general x4v3 ONNX model runs in a tiled ONNX Runtime WebAssembly worker and produces a 4× PNG on the same image layer; the original stays available for Undo and restore. The model is served with the app and inference does not upload image pixels. Saved recipes can enable or disable the operation, and bulk application runs it independently from each target image's source under the same serialized local-model lane. The worker uses up to four CPU threads when cross-origin isolation is available and one otherwise, then reserves that CPU share from concurrent Pillow-RS renders. To bound memory, sources are limited to 524,288 pixels and a 2,048-pixel edge, with an 8,388,608-pixel/64 MiB output cap. The full browser workflow and representative phone quality, latency, and low-memory behavior have not yet been validated; these limits are not a mobile performance guarantee.

Image layers also provide **Remove background · local AI**. It runs the bundled ISNet ONNX model in one serialized, one-thread WebAssembly worker, creates a full-resolution transparent PNG, and switches the selected image layer in place. The original image asset remains available for Undo, reset, and reload; the visible layer keeps its identity. Saving a recipe captures the background-removal operation, so applying it to a batch segments each target's own original image and never copies the recipe source's cutout. The batch bar lets users set the in-flight limit up to the device CPU budget. Background removal, expansion, object erase, and subject isolation share one serialized local-model lane; while inference runs, Pillow-RS render admission temporarily yields one CPU slot without terminating warm render workers. Saved object-erase recipes reserve this same slot and the bar counts model and render work together. Processing is limited to 4,194,304 source pixels and 64 MiB per background-removal source; browser and real-phone quality, memory, and throughput checks remain pending.

Interactive object isolation is also local: select an image, choose **Select area**, mark the subject with Include/Exclude strokes or a Lasso, then choose **Isolate**. A pinned MagicTouch model runs in a dedicated CPU WebAssembly worker and creates a full-source-size transparent PNG layer above the image. The source layer and its bytes stay unchanged, so the result is independently editable and can be undone as a normal layer insertion. To bound phone memory, isolation currently accepts sources up to 4,194,304 pixels and processes one image at a time. Model quality and latency still need the deferred browser workflow and real-phone checks; this limit is not a production-scale device guarantee.

Raster images copied from another app can be pasted onto the canvas with the native paste shortcut. The clipboard bytes use the same local import, memory-budget, and Pillow-RS preview path as dropped or selected files; text paste remains available in text editors, and internal layer copy/paste still works.

The editor supports editable vector paths and graph-backed Pen networks with shared junctions, branching strokes, closed fill regions with independent color and opacity, per-edge Bézier handles, curve-preserving point insertion, topology-aware point deletion, and a contour-direction control that preserves curve geometry. Smart Animate pairs vector-network records by stable IDs, so storage order may differ while edge direction and face traversal must still match. Networks can be used as live Boolean operands and alpha or vector masks. Other features include layer grouping and ungrouping, bounds-aware multi-selection alignment and distribution, shared resize and rotation handles for multi-selected layers through rotated parents, copy/cut/paste/duplicate layer actions with undo and redo, live non-destructive Boolean groups with editable shape and text sources, including variable-mode-resolved content and typography, baking supported Boolean results into editable compound vector paths, and editable alpha-mask groups with vector or text sources; baking supports rectangles with independent rounded corners converted exactly from renderer quadratics to editable cubics and smoothed circular arcs approximated by editable tangent cubics, ellipses approximated as cubic paths within 1e-6 of its source-size longer semiaxis because native paths do not store exact conic arcs; Boolean group resizing scales that error with the geometry, polygons, stars, straight closed paths, cubic Bézier paths, and networks with closed planar face cycles, including adjacent faces that share an edge; open or unfilled edges, parallel edges, edges used by more than two faces, and constrained handle modes remain unsupported, with transversal, numerically isolated intersections. Axis-aligned cubic contours that meet tangentially only at their bounds are also supported, and unsupported geometry is refused with an explanation. Rectangles, frames, sections, and image layers support independent corner radii and shared 0–100% corner smoothing, including an iOS 60% preset. Regular polygons and stars support uniform vertex radius and smoothing; stars support up to 60 points and expose Points, Ratio, and Radius handles when selected. These settings persist through component overrides and `.fig` import; Canvas, hit testing, SVG, and Boolean baking use shared geometry. Inspect CSS identifies curves CSS cannot represent, and Inspect JSON retains the editable radius and smoothing values. Shapes also support solid, linear, radial, and angular fills with editable color stops, clipped image fills with Fill/Fit scaling, repeated Tile fills with adjustable scale, quarter-turn rotation, and flips, and local Pillow-RS adjustments, 16 layer blend modes and 16 individual fill/stroke paint blend modes, drop shadows, inner shadows, foreground layer blur, and alpha-masked background blur that samples prior canvas content while leaving the layer fills crisp; SVG export explains when background blur cannot be preserved because filters cannot sample pixels behind a layer. Text boxes with fixed-size, auto-height, and auto-width behavior, editable system font families, the 100–900 weight scale, italic styling, line height, paragraph spacing, first-line indentation, per-paragraph alignment and lists, text case, vertical alignment, and underline or strikethrough. Paragraph spacing and first-line indentation affect wrapping, auto-sizing, canvas rendering, reusable text styles, SVG export, and the Inspect HTML/React/Vue and CSS handoff. Text can be selected and formatted inline with bold, italic, font family, weight, size, letter spacing, decoration, and color controls; mixed run styles affect layout, rendering, and SVG export. Text layers also support ordered solid, linear, radial, angular, and image fills, individual fill/stroke paint blending, and glyph-outline strokes; explicit layer fills take precedence over the legacy text color, while per-run solid colors remain available when a layer fill stack is absent. Reusable text styles link font family, size, weight, style, line height, letter spacing, paragraph spacing, first-line indentation, case, and decoration across text layers; updating a style refreshes linked layers immediately while color, alignment, and resizing remain local. Styles can be renamed, detached, and deleted without losing the layers’ current appearance. The editor also supports selection and transforms, multi-select, horizontal and vertical auto layout, grid auto layout with independent row and column gaps, fixed, content-hugging, and weighted fill sizing for each track, manual cell placement and spans, per-layer minimum and maximum sizing in auto layout, responsive frame constraints, frame layout guides, an outline view, and review-before-apply auto-layout suggestions for clear rows, columns, and complete grids. The Inspect panel shows resolved layer values and provides copyable nested HTML scaffolding, CSS, React JSX, Vue 3 single-file component scaffolding, and exact local layer JSON. Layers also support ordered stacks of up to 32 independently editable solid or linear, radial, and angular gradient strokes, with per-stroke paint, width, opacity, visibility, cap, join, standard or custom dash lengths, and miter limit; custom dash lengths remain editable and survive SVG and `.fig` import, Canvas rendering, and Smart Animate. Text wrapping offers Auto, Balance, and Pretty at layer and paragraph level, including rich text without losing inline formatting. Auto uses grapheme-safe fallback, CJK punctuation-aware breaks, and Thai dictionary boundaries when `Intl.Segmenter` is available; long unbroken tokens wrap without compressing the whole line. Balance and Pretty use bounded reflow and fall back to Auto for unsupported shaping cases. The framework scaffolds are adaptable starting points: app-specific local image sources and vector/mask rendering must be connected in the destination app. Inspect also supports linked components, instances and variant sets; the Assets panel can edit set names, axes, and per-variant values and place an exactly selected variant. It also supports reusable color styles with linked update, rename, and delete workflows, plus typed variables with per-mode aliases and frame-level theme overrides. Variable bindings can drive paint, text, typography, opacity, radius, visibility, and Auto Layout direction, alignment, distribution, spacing, padding, grid counts, and wrap behavior. Images use local Pillow-RS WebAssembly for exposure, temperature, tint, brightness, contrast, saturation, sharpness, blur, auto-contrast, posterize, solarize, invert, crop, quarter-turn rotation, and horizontal and vertical flips, with each render starting from the original image held in memory so edits do not compound; those settings stay editable after reload and are captured in image recipes. Image fills reference those same local image sources and remain editable after reload or `.flocal` export. Saved image recipes can be applied to a multi-selection from the canvas or Layers panel using an in-place batch bar with live pause, cancel, progress, worker controls, pause-aware images-per-second and ETA, and a retry action for failed images. On phones, Layers Select toggles any layer type without modifier keys; recipes still apply only to selected images. Local design files can be imported and exported as `.flocal` packages. SVG imports convert supported vector primitives, paths, graph metadata and styled rich text runs into editable layers inside an editable frame; unsupported geometry, paint, and unsafe content are rejected rather than flattened silently. SVG export preserves editable vector shapes, network topology, and text, embeds local raster layers and unadjusted image fills, and supports vector alpha-mask groups, Boolean union/subtract/intersect/exclude, crop and quarter-turn image transforms, repeated Tile image layers and fills scaled from original source dimensions, solid/linear/radial/angular shape fills, shadows, blur, layer blending, and individual fill/stroke paint blending. Paint blending uses earlier artwork inside the SVG as its backdrop; SVG export fails closed when opacity, effects, masks, Boolean compositing, or layer blending isolates that backdrop. A standalone SVG cannot blend against pixels outside its own document. Exclude operations preserve their vector operands and use alpha-correct SVG XOR filter composition. Edited images are embedded from local PNG previews. SVG still rejects unsupported Boolean blending, open-vector or Boolean layer mask sources, and unsupported gradient placements; importing foreign SVG paths does not invent graph editing topology.

On the canvas, Alt/Option-drag creates a fresh copy after a real drag begins. Dragging an Auto Layout child duplicates it in the same parent and reorders the copy under the pointer. A click alone creates no copy, and canceling a drag restores the original selection; the copy and its movement undo or redo together.

Canvas selection supports both rectangular marquee and freeform Lasso Select (`Q`). Lasso hit testing follows transformed and clipped layer geometry, bounds pointer samples for long gestures, and selects intersecting layers. Touch and pen gestures add to an existing selection; switch to Select and tap empty canvas space to clear before making a fresh selection.

Pencil draws uniform editable vector networks with mouse or touch. A stylus adds pressure-sensitive strokes that become closed editable vector outlines with round caps and bounded joins; hold Shift while starting a stylus stroke to keep a uniform-width network.

Offset Vector edits a selected closed path from the Inspector. Positive amounts expand the outline and negative amounts contract it; choose square or round joins, then apply or press Enter. The result stays an editable path and is a single undoable change. Cubic segments are flattened within a bounded local tolerance before offsetting. Open paths, self-intersections, touching/overlapping contours, topology changes, and geometry-bound or auto-layout layers are refused with an explanation.

Component slots turn a nested frame, group, or section in a main component into a replaceable content area. On an instance, Choose content or Replace opens a searchable picker of layers on the current page; applying copies the selected layer trees into the slot and leaves their originals in place. Reset restores the component's default slot content. Custom slot content is local to each instance, survives component sync, save/reload, and detach, and carries across variant changes when the destination variant has a slot with the same name.

Owner components can expose nested instances from a selection dialog. Apply the selection as one undoable change; the Inspector checks the 100-property limit before saving. Selecting the parent instance reveals every component property from each exposed nested instance's current component, follows nested instance swaps, includes properties added later, and hides the nested controls while that instance is hidden. Hovering or keyboard-focusing a property outlines its target layer on the canvas. Edits remain local to that nested instance, survive synchronization and save/reload, and remain intact if the owner later hides the exposure.

Component sets can be managed in Assets: rename the set, add or rename variant axes, edit each variant’s axis values, add a variant by copying the selected master into a fresh component tree, and remove an axis only when the remaining axes still distinguish every variant. Assets provides a persistent variant chooser and per-variant Place controls so the chosen master is instantiated exactly. New axes start with a shared value that can be customized per variant. Variant creation requires a source master; the editor does not generate new component artwork from a prompt.

Auto-layout suggestions analyze direct visible children of a selected frame and preview inferred horizontal rows, vertical columns, or complete regular grids. Review the inferred settings before applying; stale suggestions and changes that would move or resize a child beyond tolerance are rejected. Uncertain visible layers remain in absolute positioning, and analysis is capped at 2,048 children. See [Auto-layout suggestions](docs/auto-layout-suggestions.md) for the supported patterns and limits.

Local component libraries are shared across designs in the same browser profile and stay on this device. Publish a main component from the Assets panel, place linked instances in another design, and publish edits as new revisions. Existing instances can update to a newer revision while keeping compatible local overrides and their canvas placement; detaching leaves the layer tree editable in that design.

SVG import is local and converts supported primitives and compound vector paths into editable path layers, preserving each contour's closure, nonzero or even-odd fill rules, groups, solid paints, supported gradients, transforms, and viewBox sizing. Compound contours share one path box and remain independently editable. It imports plain text and ordered nested `<tspan>` runs into native rich-text layers, preserving supported per-run font family, size, weight, style, line height, letter spacing, decoration, and solid color. Text anchors, simple text styling, and positive uniform scale/rotation are retained. Scripts, event handlers, linked images, external references, CSS classes, unsupported filter primitives or branched graphs, per-character positioning, unsupported text opacity or paint, unsupported baselines, and unsupported transforms are rejected rather than silently flattened or dropped. Linear `feGaussianBlur` and `feDropShadow` chains map to editable effects. Text import requires `dominant-baseline="text-before-edge"`; other baseline metrics depend on the source font and cannot be represented exactly by the native text layer.

Pages can be renamed, duplicated with fresh layer identities, reordered, and deleted while preserving at least one page. The layer tree supports collapse, search that reveals matching descendants, arrow-key navigation, and a keyboard-openable actions menu. Sidebar and Inspector tablists support Left/Right, Home, and End navigation with labeled tab panels. Layer order can be changed by dragging rows or by the touch-sized up/down controls on a selected row; both operations support undo and redo. Each layer row also has touch-sized controls on phones. Prototype interactions can be guarded by typed variable equality or inequality conditions, evaluated against the active presentation mode and the layer's resolved frame mode. Prototype actions can set variables to literal values or bounded number, string, and Boolean expressions that evaluate in the active presentation; variable expressions use the unambiguous aliases shown by the editor. Named prototype flows retain independent starting frames and let a design choose which journey opens in presentation. On phones, closed side panels leave keyboard and screen-reader navigation, opening moves focus into the panel, and dismissing restores focus to its toggle.

Image processing and memory: Pillow-RS workers decode and transform image pixels; the browser Canvas2D renderer draws the resulting previews and composites them with vector, text, and other layers. The vendored WASM build uses Pillow-RS package version `12.2.0-alpha.5` from upstream `main` at commit [`06b738f`](https://github.com/appunni-m/pillow-rs/commit/06b738f99f16e222ea15d9850c8394cfe4e11937). The local patch at [patches/pillow-rs/encode-quality.patch](patches/pillow-rs/encode-quality.patch) exposes JPEG/WebP quality options in the Pillow-RS worker. `npm run build:wasm` checks out that exact commit, requires Rust 1.96.1 and wasm-pack 0.15.0, disables optional wasm-opt, then refreshes `wasm/runtime.json`, which records source and patch hashes, build tools, and local WASM file hashes. Pillow-RS documents [operation- and mode-specific limitations](https://appunni-m.github.io/pillow-rs/compatibility/) and warns that alpha APIs may break. Tiny Image Star therefore relies only on locally tested operations and must rerun its WASM regression suite before changing the pinned runtime. Before creating a browser bitmap, image import and restore inspect the header and reject sources above the 80-million-pixel limit. The preflight currently recognizes PNG, JPEG, GIF, BMP, WebP, and PNM headers and scans at most 1 MiB; unknown or unusually long headers fail closed because compressed file size cannot safely predict decoded memory. The editor also accounts for retained source bytes, fallback bitmaps, rendered previews, pending decodes, and preview replacement reservations under a device-tiered 96–384 MiB budget (160 MiB when device memory is unavailable). Under pressure it drops offscreen previews first, then least-recently-used nonvisible image sources and fallback bitmaps; originals reload from local storage when needed. Visible, selected, rendering, restoring, exporting, and package-build sources remain protected. The worker pool starts at up to two workers, and the batch speed control can raise the requested maximum to the detected CPU count (falling back to four when unavailable), capped at eight. Actual active workers can be lower when image size approaches the render budget; the batch bar shows the requested maximum and current active workers. Concurrent Pillow-RS jobs share a 192/320/640/1024 MiB device tier (256 MiB when device memory is unknown), with a separate per-image hard ceiling of 192 MiB on devices up to 2 GiB, 320 MiB up to 4 GiB, and 512 MiB otherwise. The estimate uses 32 bytes per source pixel for WASM and encoder working memory; unknown headers receive the full 80-million-pixel estimate and are rejected by the per-image ceiling. These estimates do not measure all browser memory, so large designs can still be constrained by available device memory. When a decoded image fits its worker cache, Pillow-RS keeps the full-resolution source for successive edits. If it exceeds the cache budget, each preview decodes the full source from the editor-retained original bytes and releases the worker's decoded copy after rendering; later edits still start from the same original, with extra decode time in exchange for bounded cache memory. Exports also decode from the retained original bytes. Changing selection releases the active-source priority. Images above the per-image working-set ceiling remain blocked before decoding, regardless of cache size.

Prototype interactions can connect layers to frames with click/tap, hover, or after-delay triggers; after-delay waits are configurable from 100 ms to 10 seconds and are canceled when presentation navigation changes the active frame or the presentation closes. Scroll-to-layer actions reveal nested targets in the current scrollable frame with nearest, start, center, or end alignment and optional animated easing. Flows can set a starting point, configure transitions including Smart Animate with linear, ease-in, ease-out, ease-in-out, back, spring, or custom cubic-Bézier timing, open or swap centered or edge-positioned overlays, open validated web and mail links, go back through navigation history, set a variable collection's mode for the active presentation, dim the presentation background, and dismiss overlays from their own interactions or outside clicks. Overlay presentation renders the base scene, dimmer, and top overlay as separate local canvas layers, so directional opening, swapping, and dismissal keep the underlying scene in place; Back and outside dismissal reverse the transition stored with the opened overlay. Smart Animate is available for matching layers during frame navigation and overlay swaps. Browser visual validation for overlay stacking and mobile motion is still pending. Smart Animate matches layers by name and parent hierarchy, interpolates geometry and rotation along the shortest arc, opacity, numeric text metrics, compatible solid colors, and compatible drop-shadow, layer-blur, and background-blur effect stacks. Text content and variable- or style-bound paint semantics switch at the midpoint; matched text layers keep their interpolated geometry while their content changes at the midpoint. Compatible unbound gradients of the same type and stop count interpolate their angle, stop positions, and colors. Eligible unbound fill entries crossfade across paint types, incompatible gradient topology, image asset or fill-mode changes, and image-transform topology changes when both image fills have default adjustments; compatible same-asset image crops interpolate directly from the original bitmap. Image fills with non-default adjustments and variable- or style-bound paints retain their midpoint snapshot behavior. Unadjusted image layers and fills render animated crop, rotation, and flip values from the in-memory source instead of reusing an endpoint preview. Compatible vector paths with the same contour count and matching per-contour closure and point counts morph all anchors and Bézier handles. Compatible vector networks with unchanged vertex/edge/face topology morph their vertices and Bézier controls; incompatible paths and networks crossfade. These links are stored with the local document.

Canvas comments support anchored review threads, replies, resolution, and deletion. Threads are stored in the design snapshot and included in `.flocal` exports. During a live peer session, a guest's comment changes are saved to the guest's local copy, sent with the full snapshot, and shown on the owner only after the owner commits the new revision and returns a durable ACK. Without an active session, comments remain local to that design copy; no cloud comment service is involved.

The Motion inspector adds local keyframed tracks for layer X/Y position, width, height, rotation, and opacity, plus animated color and opacity for the first solid fill. Set a duration, add a track, edit its keyframe values and easing, scrub the timeline, and play a read-only canvas preview. Authored layer values remain unchanged during preview, and timeline edits participate in local save, undo, and redo. This timeline remains independent of Prototype Smart Animate and does not yet export animation files or animate text or effects.

This is an active rebuild, not production certification or complete parity with mature collaborative design tools. Boolean previews use a bounded-resolution local canvas composite while keeping their source vectors and text editable, and resizing scales source geometry into the group bounds. Baking supported Boolean results creates native compound paths and preserves supported cubic Bézier handles; square-corner rectangles, ellipses approximated as cubic paths within 1e-6 of its source-size longer semiaxis (with error scaled by Boolean group resizing), polygons, stars, and closed paths are supported for transversal, numerically isolated intersections; axis-aligned cubic contours that meet tangentially only at their bounds are also supported. Vector networks with open or unfilled edges, parallel edges, edges used by more than two faces, smooth or symmetric handle modes, split-edge restoration metadata, or translucent faces, plus transparency, blending, mode-bound geometry, component content, other tangent or ambiguous intersections, and inputs above explicit complexity limits remain unsupported. Linked component instances retain local property, geometry, and child-order overrides while main component structure and styling synchronize. Component sets support named variant properties, per-instance variant switching, and override migration across structurally matching layers. Main components support reusable Boolean visibility, text, and nested instance-swap properties; linked instances expose those values in the Inspector. Component slots expose nested frames, groups, and sections as replaceable instance content. Inspect provides adaptable React JSX and Vue 3 single-file component scaffolds alongside HTML, CSS, and exact layer JSON; app-specific image and vector rendering still needs to be connected in the destination project. Further work remains on advanced vector operations, richer typography and layout controls, wider Smart Animate parity, real-device multi-guest collaboration validation, local prompt-based image generation and editing, and broader `.fig` import coverage. SVG editable alpha-mask groups support rectangle, ellipse, star, polygon, text glyphs, closed paths, and networks with closed regions; Boolean alpha masks also preserve text glyphs and their resolved variable-mode content and typography. Editable mask-group sources that are open paths or networks, Boolean layers, or blended layers remain unsupported; Boolean operands with non-normal blend modes, raster adjustments without an available rendered preview, and unsupported gradient placements are not represented. Boolean unions, subtraction, intersection, and exclude export their editable vector and text operands through SVG alpha masks and apply the same source-bounds resize transform as the canvas; exclude combines sequential operands with alpha-correct XOR filters. Crop and quarter-turn rotation export directly from the local source raster, while edited images embed the current local PNG preview. `.fig` import is experimental and best effort: it does not provide full fidelity, round-trip preservation, or compatibility guarantees for future versions of the proprietary format; see [the import readiness notes](docs/fig-import-readiness.md). Cloud services and live API access are not implemented.

Layer effects include ordered drop-shadow and inner-shadow stacks, one layer or background blur, up to two deterministic Noise effects, and one Texture effect per layer. Noise offers Mono, Duo, and Multi color modes with separate X/Y grain size, density, color, and opacity controls. Texture distresses object edges with X/Y size, radius, and Clip to shape controls; deterministic edge-mask work is capped at one megapixel. Reusable effect styles save, apply, update, and delete complete stacks. Noise and Texture use stable local seeds. Canvas rendering applies layer blur, noise, and texture in their authored order, then inner shadows and drop shadows in Figma's documented paint phases; background blur and Glass use a separate backdrop pass. Top effects currently process merged layer pixels, so exact separation of stroke and fill paints remains a visual-parity check. SVG and vector-PDF export refuse visible Noise or Texture with guidance to hide/remove the effect or use raster PDF.

Frames can be exported as flattened raster PDF or as a vector PDF. The vector writer preserves supported vector shapes, paths, strokes, solid fills, linear/radial gradients with opaque stops, transforms, clipping, and bounded user-space alpha/vector masks as PDF soft-mask forms. Untouched local PNG/JPEG layers and image fills are embedded as PDF image objects (PNG transparency stays in a soft mask); supported edited, cropped, rotated, or flipped images are rendered by local Pillow-RS to lossless PNG previews before embedding, while neighboring vector artwork remains vector. Untouched WebP/GIF/AVIF and other unsupported image formats fail closed with conversion guidance. The low-level SVG-to-PDF API can represent hand-authored, single-line printable ASCII text using standard Helvetica fonts; the app's editor can also export positioned, wrapped lines for simple left-, center-, or right-aligned single-style text. Custom fonts, rich text, non-ASCII text, justified paragraphs, and other unsupported text treatments still fail with a specific explanation; use raster PDF to preserve those cases. Tile image patterns, filters, luminance/object-bounding-box masks, blend modes, and visible Noise or Texture effects also fail closed with a specific explanation; use raster PDF for unsupported artwork. A page export creates one PDF page for each visible top-level frame. Use raster PDF when the artwork includes unsupported content.

## Design tokens and prototype gestures

The layer tree supports keyboard navigation, context-menu access, and layer reordering with Alt/Option+ArrowUp or Alt/Option+ArrowDown; touch and pen reorder gestures start from a dedicated handle so ordinary panel swipes still scroll. Inspect handoff positions account for rotated parent frames, and the panel reports responsive constraints and auto-layout placement. Numeric prototype variables can guard interactions with greater-than, greater-than-or-equal, less-than, and less-than-or-equal comparisons; color, string, and Boolean variables retain equality and inequality checks. Glass adds a deterministic, backdrop-responsive local effect with controls for refraction, depth, dispersion, frost, splay, lighting angle, and intensity.

The Variables panel imports and exports DTCG token JSON on this device. Standard DTCG input supports color, number, string, pixel-dimension, and millisecond/second-duration tokens with aliases. Dimensions and durations remain local number variables while an extension preserves their semantic DTCG type; export uses pixels and milliseconds as lossless canonical units. Tiny Image Star also includes a local extension to round-trip every collection and mode; other DTCG tools see each collection's default mode. Number, color, and string variables can be scoped to Figma-compatible property pickers; scopes filter picker choices without breaking existing bindings. Boolean variables do not use scopes and export as strings because DTCG has no boolean token type. Unsupported types, units, alpha colors, and color precision the editor cannot retain are rejected rather than silently changed.

Prototype links also support on-press and on-drag triggers, plus component-instance variant changes such as hover states. Press fires on pointer-down; drag requires movement. Variant changes affect only the local presentation session and leave the saved design unchanged.

## Vector editing and alignment

The Polygon and Star tools create editable shapes. Select a polygon to set its side count, or a star to set its point count and inner-radius ratio; both shapes also have uniform vertex-radius and smoothing controls, retained in designs and editable SVG export. Vector path anchors can be set to Corner, Smooth, or Symmetric. Smooth anchors keep handles collinear while allowing their lengths to differ; converting an untouched Corner anchor to Smooth infers handles from its neighboring anchors, including at open endpoints and around closed paths. Symmetric anchors mirror handle direction and length. On phones, the anchor control remains reachable in the touch-sized properties panel.

When moving layers, the canvas snaps selection edges and centers to visible peer geometry and draws live magenta alignment guides. Hold Alt while dragging to bypass both alignment and grid snapping for that move.

Compound vector paths keep each contour editable inside one layer. Select a contour by clicking one of its anchors, then add or remove contours, insert and delete anchors, and change that contour's open or closed state in the Vector inspector. Turn on Select multiple anchors to collect points across contours on a phone or desktop; turn selection mode off and drag a selected point to move the group together. Deleting a group is atomic and refuses the edit if any contour would be left with fewer than two anchors. When deleting an interior anchor joins curved segments, the editor fits a replacement cubic while keeping unconstrained endpoint tangents; straight segments retain direct joins, and constrained Smooth or Symmetric endpoint handles remain untouched. Closed contours can use the nonzero or even-odd fill rule; SVG import, canvas fills, image-fill clipping, Boolean operands, masks, Smart Animate, local saves, and SVG export preserve the supported contour geometry.

Fills and ordered strokes support editable angular gradients with adjustable start angles and color stops. Canvas rendering and local saves preserve their appearance; editable SVG/PDF export reports when a design needs raster export to retain an angular gradient.

## Bulk recipe recovery

Before an image recipe batch changes a layer, Tiny Image Star stores a small local recovery record for the recipe, page, and target image layers. If a batch is left open or the browser closes unexpectedly, reopening that design offers two choices: resume the saved recipe across the original targets, or keep the image edits that were already saved. The result bar saves the final document before it clears the recovery record.

The in-place recipe bar starts desktop batches at up to four workers and phone or known-low-memory batches at up to two. Its live speed control can raise or lower the cap up to the reported CPU budget; Pillow-RS memory admission can still reduce actual parallelism for large images.

The canvas tool strip is a horizontal keyboard toolbar: Tab enters at one tool, arrow keys move across the strip, and Home/End reach its first and last tools. On phones, the main menu keeps **Share local design…** available while the direct top-bar Share button is hidden to preserve canvas space. Batch progress exposes concise announcements for state changes without placing its frequently updated worker controls inside a live region.
