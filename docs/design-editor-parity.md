# Tiny Image Star design-editor parity ledger

Reviewed 2026-10-02 against the current Tiny Image Star source tree and Figma's public design-editor documentation. This is a working acceptance ledger, not a claim of complete parity. The product target is Figma Design's canvas/editor workflow, implemented locally with Pillow-RS/WASM for raster work; the requested saved-recipe batch workflow is the one deliberate extension.

## Current evidence and gaps

| Area | Tiny Image Star evidence | Remaining parity work |
| --- | --- | --- |
| Canvas, pages, layers, and transforms | Nested pages/layers, selection, drawing, vector paths/networks, constraints, and responsive editor panels are implemented. Comment mode returns to component/frame selection when a canvas target is clicked; the Inspector's direct Delete action captures the target ID, including an explicit multi-selection delete. Alt/Option resizes one layer or a multi-selection from its center, with Shift aspect locking and crossing prevention. Canvas selection changes are announced through a polite live region. | No measured interaction or pixel-by-pixel comparison against Figma. Continue closing gesture, focus, and narrow-screen gaps; do not infer parity from model tests alone. |
| Auto layout | Horizontal, vertical, and grid flows, wrapping, track sizing, child sizing, and local suggestions are present. Grid tracks can be appended, deleted, and reordered from the inspector; reordering moves connected spans as one block, while deletion removes single-cell contents and contracts spanning layers. Selected grid frames now expose canvas grabbers for direct column and row resizing. Fixed-pixel and content-based minimum track bounds survive `.fig` import, local layout, reordering, and Inspect CSS output. | Unequal flexible min/max track intervals remain an approximation with import review. Run the deferred browser workflow and compare track-bound and resize behavior visually with Figma. |
| Typography | Rich-text runs, paragraph properties, reusable text styles, variable bindings, local font assets, text resizing, and editable text along vector paths, ellipses, rectangles, and lines are implemented. Locally loaded TTF, OTF, WOFF, and WOFF2 fonts expose their `fvar` axis ranges in the inspector; WOFF2 decompression and axis inspection run in bounded local workers. Axis coordinates and OpenType feature maps persist on layers, rich-text runs, text styles, component overrides, appearance clipboard data, collaboration edits, Inspect JSON, and SVG export/import. The inspector provides common feature switches plus arbitrary four-character feature tags with integer values. Canvas preview uses a pinned local HarfBuzz WebAssembly shaper for locally installed fonts and applies axes and features; shaped glyph clusters also drive text-on-path placement and auto-size measurement when available. Unsupported glyphs fall back to browser font rendering. Text-path offset and orientation are adjustable; run-specific family, size, weight, style, features, color, tracking, decoration, and baseline shift carry through Canvas preview and SVG `<textPath>` export. Same-parent source links update the path, text bounds, and transform in canvas hit-testing and SVG export; links are remapped on duplication/component creation and detach to the latest geometry when either layer moves or is deleted. | Mixed-script font fallback needs run itemization. Auto-size may use browser canvas metrics while a local shaped run is still warming, and cold-load metric reconciliation needs browser validation. Live links are not created inside auto-layout, mask, or Boolean containers; those contexts keep a geometry snapshot. Browser visual checks are still required for axis and feature fidelity, shaped text-path alignment, and mobile inspector density. |
| Vector and illustration | Editable paths and vector networks, four Boolean operations, masks, editable strokes, deterministic effects, local Shape Builder, and destructive Offset Vector are implemented. Offset Vector supports signed expansion/contraction, square or round joins, curved closed contours, even-odd holes, and affine/rotated placement preservation; the result remains editable and is one undoable path replacement. Shift-drag moves both Bézier handles together at a path anchor or degree-two network vertex. Shape Builder previews cubic regions, bakes affine transforms into editable paths, supports tap-to-extract, drag-to-merge, subtract, and pinch takeover without committing, and retains source identities where regions remain. | Offset Vector currently requires closed, non-self-intersecting contours with distinct boundaries; it refuses topology changes, overlapping contours, geometry variables, and auto-layout children. Cubics are flattened at bounded local tolerance before offsetting, so compare curve fidelity visually with Figma. Its phone browser workflow is registered but remains unrun until the feature batch is complete. Shape Builder refuses component-backed, variable-bound, hidden, transparently composited, cross-container, and unsupported/ambiguous geometry; its desktop and phone browser workflows are also deferred. Boolean baking refuses ambiguous topology and several unsupported source cases. |
| Raster editing | Original bytes remain local; Pillow-RS WASM renders non-destructive adjustments and full-resolution exports. A worker retains a decoded source only when the full image fits its cache; over-budget previews decode from the unchanged original bytes and release their working copy afterward. The editor also releases offscreen previews first, then least-recently-used nonvisible source and fallback-bitmap resources under its device-tiered memory budget, while protecting visible, selected, active, restoring, and export sources. Edited previews are rebuilt when layers or pages are duplicated; offscreen clones wait until they enter the viewport. MI-GAN runs locally in a one-thread ONNX/WASM worker for brush-based object erase. MagicTouch Interactive Segmenter v2 runs locally in a bounded CPU/WASM worker for include/exclude/lasso subject isolation; it creates a separate transparent PNG layer and keeps the source untouched. | Figma's current image-tool workflow also documents Expand image, Remove background, prompt-based editing, and resolution boost. There is no local outpainting or prompt-edit model in the editor yet; reusing MI-GAN would not be equivalent. Isolation is capped at 4,194,304 source pixels and its segmentation quality/latency still need browser and real-phone validation. Source reload and throughput behavior also need independent-profile and low-memory-phone checks. |
| Components and design systems | Component sets, variants, properties, slots, local variable collections/modes, and reusable color, text, effect, and image recipes are supported. | Validate full parity for variable scoping, library exchange, and complex nested instance workflows using real source documents. |
| Prototyping | Local flows support triggers, variables, conditions, overlays, scrolling, and Smart Animate for documented compatible properties. Frame clipping and overflow behavior now switch at the transition midpoint, including in nested frames. | Unsupported animation properties/topologies still switch or crossfade; broader Figma transition fidelity needs measured reference cases. |
| Collaboration and persistence | Designs save locally; optional folder workspaces and host-authoritative WebRTC sessions use user-relayed signaling. Guest edits require host commit/ACK; stale edits are retained as local recovery forks. Snapshot replacement cannot modify the design asset manifest; guests must use the verified asset operations. | Mobile browsers without a directory picker cannot use a selected folder as canonical storage. No automatic merge of conflicting revisions or full live-presence layer is claimed. Validate independent profiles and real devices before release claims. |
| Import and export | Local `.fig` import, SVG, raster exports, and bounded vector PDF are implemented with explicit review/fail-closed behavior. | `.fig` remains experimental and best effort, with no round-trip guarantee. Several effect, mask, image, and vector cases require raster fallback or are refused. |
| Saved image recipes (requested extension) | Right-click an edited image to save a recipe, multi-select image layers, apply it in place, and use the progress bar to pause, cancel, retry, and set a worker cap. The bar reports current batch workers against that cap. | Finish full lifecycle validation for very large batches, lower-memory phones, cancellation/recovery, and reload/export paths before making a production-scale throughput claim. |

The current feature descriptions and detailed technical limits live in the [README](../README.md), [`.fig` import readiness notes](fig-import-readiness.md), and [local workspace and sharing design](local-folder-sharing-design.md). Those documents are the source of truth for the implementation's exact limits; this table highlights product-level gaps.

## Verification policy

Node tests and `npm run verify:static` verify local model behavior, worker packaging, and static deployment inputs. They do not prove editor interaction or visual parity. Browser smoke remains deferred until the current feature batch is implemented, as requested; afterward, run the complete browser workflow and focused mobile flows, record failures, and fix them together before release review. Real-device and independent-profile checks remain separate evidence required for mobile persistence, sharing, and performance claims.

The text-on-path distance table is capped at 65,536 samples and is built once per canvas draw, then queried with binary search for each glyph. A local synthetic Node microbenchmark with 400 curved anchors and 156 graphemes measured 28.58–33.18 ms when rebuilding the table per glyph versus 0.23–0.32 ms with one reused table (five paired samples after two warmups; diagnostic only, not a browser or device guarantee).
