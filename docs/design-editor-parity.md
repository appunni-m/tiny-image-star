# Tiny Image Star design-editor parity ledger

Reviewed 2026-10-02 against the current Tiny Image Star source tree and Figma's public design-editor documentation. This is a working acceptance ledger, not a claim of complete parity. The product target is Figma Design's canvas/editor workflow, implemented locally with Pillow-RS/WASM for raster work; the requested saved-recipe batch workflow is the one deliberate extension.

## Current evidence and gaps

| Area | Tiny Image Star evidence | Remaining parity work |
| --- | --- | --- |
| Canvas, pages, layers, and transforms | Nested pages/layers, selection, drawing, vector paths/networks, constraints, and responsive editor panels are implemented. The Inspector now exposes a direct Delete layer action that captures the target ID, including an explicit multi-selection delete. | No measured interaction or pixel-by-pixel comparison against Figma. Continue closing gesture, focus, and narrow-screen gaps; do not infer parity from model tests alone. |
| Auto layout | Horizontal, vertical, and grid flows, wrapping, track sizing, child sizing, and local suggestions are present. | Figma's Grid flow is still evolving; verify add/reorder/resize and manual placement behavior against current Figma. `.fig` grid min/max track bounds can be approximated and reported. |
| Typography | Rich-text runs, paragraph properties, text styles, variable bindings, local font assets, text resizing, and editable text along vector paths, ellipses, rectangles, and lines are implemented. Text-path offset and orientation are adjustable; run-specific family, size, weight, style, color, tracking, decoration, and baseline shift now carry through Canvas preview and SVG `<textPath>` export. | Text uses a geometry snapshot rather than a live source-path link. Variable-font axes and OpenType feature controls remain gaps. Browser canvas text metrics/rendering also need visual parity checks across platforms. |
| Vector and illustration | Editable paths and vector networks, four Boolean operations, masks, editable strokes, and deterministic effects are implemented. | Figma Draw workflows such as Shape Builder and Offset Vector are not yet fully represented. Boolean baking intentionally refuses ambiguous topology and several unsupported source cases. |
| Raster editing | Original bytes remain local; Pillow-RS WASM renders non-destructive adjustments and exports. MI-GAN runs locally in a one-thread ONNX/WASM worker for brush-based object erase. | Figma's current image tools also include subject isolation and image expansion. The bundled MI-GAN model is an inpainting model, not an outpainting or segmentation model; reusing it must not be presented as equivalent output quality. |
| Components and design systems | Component sets, variants, properties, slots, local variable collections/modes, and reusable color, text, effect, and image recipes are supported. | Validate full parity for variable scoping, library exchange, and complex nested instance workflows using real source documents. |
| Prototyping | Local flows support triggers, variables, conditions, overlays, scrolling, and Smart Animate for documented compatible properties. | Unsupported animation properties/topologies still switch or crossfade; broader Figma transition fidelity needs measured reference cases. |
| Collaboration and persistence | Designs save locally; optional folder workspaces and host-authoritative WebRTC sessions use user-relayed signaling. Guest edits require host commit/ACK; stale edits are retained as local recovery forks. | Mobile browsers without a directory picker cannot use a selected folder as canonical storage. No automatic merge of conflicting revisions or full live-presence layer is claimed. Validate independent profiles and real devices before release claims. |
| Import and export | Local `.fig` import, SVG, raster exports, and bounded vector PDF are implemented with explicit review/fail-closed behavior. | `.fig` remains experimental and best effort, with no round-trip guarantee. Several effect, mask, image, and vector cases require raster fallback or are refused. |
| Saved image recipes (requested extension) | Right-click an edited image to save a recipe, multi-select image layers, apply it in place, and use the progress bar to pause, cancel, retry, and set a worker cap. The bar reports current batch workers against that cap. | Finish full lifecycle validation for very large batches, lower-memory phones, cancellation/recovery, and reload/export paths before making a production-scale throughput claim. |

The current feature descriptions and detailed technical limits live in the [README](../README.md), [`.fig` import readiness notes](fig-import-readiness.md), and [local workspace and sharing design](local-folder-sharing-design.md). Those documents are the source of truth for the implementation's exact limits; this table highlights product-level gaps.

## Verification policy

Node tests and `npm run verify:static` verify local model behavior, worker packaging, and static deployment inputs. They do not prove editor interaction or visual parity. Browser smoke remains deferred until the current feature batch is implemented, as requested; afterward, run the complete browser workflow and focused mobile flows, record failures, and fix them together before release review. Real-device and independent-profile checks remain separate evidence required for mobile persistence, sharing, and performance claims.

The text-on-path distance table is capped at 65,536 samples and is built once per canvas draw, then queried with binary search for each glyph. A local synthetic Node microbenchmark with 400 curved anchors and 156 graphemes measured 28.58–33.18 ms when rebuilding the table per glyph versus 0.23–0.32 ms with one reused table (five paired samples after two warmups; diagnostic only, not a browser or device guarantee).
