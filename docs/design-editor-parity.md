# Tiny Image Star design-editor parity ledger

Reviewed 2026-10-03 against the current Tiny Image Star source tree and Figma's public design-editor documentation. This is a working acceptance ledger, not a claim of complete parity. The product target is Figma Design's canvas/editor workflow, implemented locally with Pillow-RS/WASM for raster work; the requested saved-recipe batch workflow is the one deliberate extension.

## Current evidence and gaps

| Area | Tiny Image Star evidence | Remaining parity work |
| --- | --- | --- |
| Canvas, pages, layers, and transforms | Nested pages/layers, selection, drawing, vector paths/networks, constraints, and responsive editor panels are implemented. Comment mode returns to component/frame selection when a canvas target is clicked; on phones, saved comment review reserves a separate canvas hit area beside the comments panel. A new-comment draft keeps the mobile canvas available; selecting a component or frame preserves its anchor and unsent text, which return when the user reopens Comments. Touch and pen long-press on a layer in Select opens the existing context menu. The Inspector's direct Delete action captures the target ID, including an explicit multi-selection delete. Alt/Option resizes one layer or a multi-selection from its center, with Shift aspect locking and crossing prevention. Canvas selection changes are announced through a polite live region. | No measured interaction or pixel-by-pixel comparison against Figma. Continue closing gesture, focus, and narrow-screen gaps; do not infer parity from model tests alone. |
| Rounded-corner geometry | Rectangles, frames, sections, and images support shared 0–100% corner smoothing, an iOS 60% preset, independent radii, and component overrides. Polygons and stars expose uniform or independent per-vertex radii and smoothing. Their canonical path is shared by Canvas rendering, visible-geometry hit testing, SVG export, component overrides, `.fig` import, and Boolean baking; independent values also survive appearance copy/paste, document reload, Inspect output, and Smart Animate when shape topology matches. Vector networks now expose per-vertex radii on simple unshared closed regions; renderer, fill/stroke picking, SVG export/import metadata, and Boolean baking share the rounded path. | Network radii are disabled for branched, shared, or ambiguous boundaries, and radii on curved corners use a tangent cubic bridge approximation. Compare the control behavior and generated curves visually with Figma before claiming pixel-level parity, especially for tight concave star points, smoothing under edge-budget clamps, and curved network corners. |
| Auto layout | Horizontal, vertical, and grid flows, wrapping, track sizing, child sizing, and local suggestions are present. Grid tracks can be appended, deleted, and reordered from the inspector; reordering moves connected spans as one block, while deletion removes single-cell contents and contracts spanning layers. Selected grid frames now expose canvas grabbers for direct column and row resizing. Fixed-pixel, content-based, and non-contradictory flexible-to-fill minimum bounds survive import, local layout, reordering, and serialization. Inspect CSS includes the maximum flexible sizing and calls out fractional lower bounds that CSS Grid cannot express directly. | The local fractional minimum rule uses the maximum fill tracks' base flexible unit as its reference; incompatible or contradictory bounds still warn and fall back to the maximum. [Figma's public grid guide](https://help.figma.com/hc/en-us/articles/31289469907863-Use-the-grid-auto-layout-flow) explains fill-track fractions and min/max settings but does not specify how two fractional bounds interact; compare real .fig files in the deferred browser workflow before claiming exact parity. |
| Typography | Rich-text runs, paragraph properties, reusable text styles, and typed variable bindings for font family, weight, style, size, line height, tracking, paragraph spacing, first-line indent, and content are implemented. Bound typography resolves through inherited modes in the inspector, canvas, auto-sizing, live text editing, and SVG export. Truncation settings persist through local files, component overrides, `.fig` import (including legacy `TRUNCATE`), and collaboration operations; canvas and SVG export use the same measured grapheme-safe ellipsis layout and clip to the authored text box. Locally loaded TTF, OTF, WOFF, and WOFF2 fonts expose their `fvar` axis ranges in the inspector; WOFF2 decompression and axis inspection run in bounded local workers. Axis coordinates and OpenType feature maps persist on layers, rich-text runs, text styles, component overrides, appearance clipboard data, collaboration edits, Inspect JSON, and SVG export/import. The inspector provides common feature switches plus arbitrary four-character feature tags with integer values. Canvas preview uses a pinned local HarfBuzz WebAssembly shaper for locally installed fonts and applies axes and features; script and cmap coverage now split mixed text into grapheme-safe local-shaper and browser-fallback runs. Shaped glyph clusters also drive text-on-path placement and auto-size measurement when available. Text-path offset and orientation are adjustable; run-specific family, size, weight, style, features, color, tracking, decoration, and baseline shift carry through Canvas preview and SVG `<textPath>` export. Same-parent source links update the path, text bounds, and transform in canvas hit-testing and SVG export; links are remapped on duplication/component creation and detach to the latest geometry when either layer moves or is deleted. | The bundled script itemizer covers common writing systems; uncommon scripts intentionally stay on the browser font stack. Auto-size may use browser canvas metrics while a local shaped run is still warming, and cold-load metric reconciliation needs browser validation. Live links are not created inside auto-layout, mask, or Boolean containers; those contexts keep a geometry snapshot. Browser visual checks are still required for axis and feature fidelity, shaped text-path alignment, truncation fidelity, and mobile inspector density. |
| Vector and illustration | Editable paths and vector networks, four Boolean operations, editable alpha masks plus bounded vector masks, editable strokes, deterministic effects, local Shape Builder, and destructive Offset Vector are implemented. Offset Vector supports signed expansion/contraction, square or round joins, curved closed contours, even-odd holes, and affine/rotated placement preservation; the result remains editable and is one undoable path replacement. Shift-drag moves both Bézier handles together at a path anchor or degree-two network vertex. Stars support the current 3–60 outer-point range and selected stars expose direct Points, Ratio, and corner Radius canvas handles; Inspector, `.fig` import, components, Boolean validation, and SVG export share the same bound. The `.fig` importer now keeps simple single-region vectors and multiple one-loop regions as editable network layers, including cubic handles; multi-loop holes, styled regions, strokes, and complex graphs continue as editable path groups when resolved paths can be preserved. Shape Builder previews cubic regions, bakes affine transforms into editable paths, supports tap-to-extract, drag-to-merge, subtract, and pinch takeover without committing, and retains source identities where regions remain. | Figma documents star count, inner ratio, and rounding in [Shape tools](https://help.figma.com/hc/en-us/articles/360040450133-Shape-tools). The new star handles have unit coverage but need the deferred desktop/phone browser interaction and visual checks. Offset Vector currently requires closed, non-self-intersecting contours with distinct boundaries; it refuses topology changes, overlapping contours, geometry variables, and auto-layout children. Cubics are flattened at bounded local tolerance before offsetting, so compare curve fidelity visually with Figma. Its phone browser workflow is registered but remains unrun until the feature batch is complete. Shape Builder refuses component-backed, variable-bound, hidden, transparently composited, cross-container, and unsupported/ambiguous geometry; its desktop and phone browser workflows are also deferred. Boolean baking refuses ambiguous topology and several unsupported source cases. |
| Raster editing | Original bytes remain local; Pillow-RS WASM renders non-destructive adjustments and full-resolution exports. A worker retains a decoded source only when the full image fits its cache; over-budget previews decode from the unchanged original bytes and release their working copy afterward. The editor also releases offscreen previews first, then least-recently-used nonvisible source and fallback-bitmap resources under its device-tiered memory budget, while protecting visible, selected, active, restoring, and export sources. Image layers and image fills also support Figma-style Tile repetition at a configurable percentage of the original source dimensions; preview scaling does not change the repeat period, and saved crop data remains available when switching back to Fill or Fit. Edited previews are rebuilt when layers or pages are duplicated; offscreen clones wait until they enter the viewport. MI-GAN runs locally in a one-thread ONNX/WASM worker for brush-based object erase and a basic unprompted Expand operation on the same image layer; source pixels and geometry remain recoverable. MagicTouch Interactive Segmenter v2 runs locally in a bounded CPU/WASM worker for include/exclude/lasso subject isolation; it creates a separate transparent PNG layer and keeps the source untouched. ISNet background removal runs locally in a bounded one-thread WebAssembly worker and replaces the active asset on the same image node while retaining the original asset for Undo and restore. Background removal, expansion, object erase, subject isolation, and resolution boost share one serialized local-model lane. Inference reserves one to four CPU slots according to the operation and cross-origin isolation, draining Pillow renders to the remaining cap without destroying warm render workers; saved recipes count inference and renders in the same live worker budget. | Figma's current image workflow includes text-to-image generation, reference-image-guided prompt editing, and resolution boost; [Figma documents these image AI tools](https://help.figma.com/hc/en-us/articles/24004542669463-Generate-and-edit-images-with-Figma-AI). A pinned Real-ESRGAN general x4v3 ONNX conversion now powers local 4× resolution boost in a tiled ONNX Runtime WebAssembly worker; saved recipes and batch processing generate each target from its own source. The editor has no local generation or prompt-edit model. MI-GAN is not prompt-guided and resizes inference around the mask, so expand quality and latency must be measured on real photos and mobile devices before claiming parity. Background removal and isolation are capped at 4,194,304 source pixels; ISNet sources are also limited to 64 MiB. Resolution boost caps sources at 524,288 pixels and 2,048 pixels per edge and outputs at 8,388,608 pixels/64 MiB. Model quality, cold-start latency, batch memory, cancellation/recovery, and low-memory-phone behavior still need the deferred browser workflow and real-device checks. The candidate models and mobile performance gate are documented in [local image enhancement research](local-image-enhancement-research.md). |
| Components and design systems | Component sets, variants, typed properties, slots, local variable collections/modes, reusable color, text, effect, layout-guide styles, and image recipes; Figma-compatible variable picker scopes are supported. A single layout guide can be selected in the Inspector and copied with Cmd/Ctrl+C, pasted to one or more selected frames with Cmd/Ctrl+V, or duplicated in place with Cmd/Ctrl+D; pasted and duplicated guides receive fresh IDs, and edited frames detach from shared styles without changing other linked frames. Owner components expose nested instances through a multi-select dialog; applying the selection validates the 100-property cap and records one undoable change. Selecting the parent instance reveals every property and variant axis from each exposed nested instance's current component, follows nested variant changes and allowed swaps, maps exposures across equivalent source layers in owner component variants, and hides the controls when the nested instance is hidden. Hovering or focusing a property outlines its matching layer on the canvas, including source-scoped targets inside nested instances. Exposure survives owner/nested synchronization and reload, and is cleaned up when its source node is removed. Scope edits for color, number, and string variables persist locally and through the Tiny Image Star DTCG extension; scope filtering follows Figma's picker-only behavior and does not revoke saved bindings. Typography variables include the Figma font and paragraph scopes and reflow bound text across modes. The `.fig` importer now retains declared variant axes/values, Boolean and text properties, nested-instance swap properties and exposure flags, and slot targets/custom content when their source links map cleanly. | Validate layout-guide copy, paste, duplicate, and the component workflows in the deferred desktop/phone browser suite and against real source documents. The importer reports multi-layer property bindings, unavailable library choices, and slot limits that the local model cannot represent. Focused Node coverage does not verify the Inspector's visual behavior. |
| Prototyping | Local flows support triggers, variables, conditions, overlays, scrolling, fixed-position layers in scrollable frames, and Smart Animate for documented compatible properties. Fixed children remain viewport-anchored during parent scrolling, paint above scrolling siblings, stay pickable at their visible position, and persist through components, `.fig` import, and collaborative property edits; auto-layout children must be Absolute first. Frame clipping, overflow, and fixed-position behavior switch at the transition midpoint, including in nested frames. Frame navigation renders outgoing and incoming snapshots for Dissolve, Move In/Out, Push, and Slide In/Out using viewport-sized motion; durations persist through 10 seconds. Presentation rendering separates the base scene, top overlay backdrop, and top overlay surface so overlay-only motion leaves the underlying page in place. Overlay entrance, swap, explicit close, Back, and outside dismissal use directional motion and easing; Back/outside dismissal reverses the transition saved with the opened overlay. Smart Animate is available for frame navigation and matching-layer overlay swaps, but not Open overlay. | Sticky positioning is not implemented. Overlay composition, directional motion, fixed positioning, and collaboration/persistence have unit coverage but still need browser visual checks for stacking, scroll anchoring, dimmer timing, cancellation, nested overlays, and mobile viewports. Unsupported Smart Animate properties/topologies still switch or crossfade; browser visual checks remain deferred until the feature batch is complete. |
| Collaboration and persistence | Designs save locally; optional folder workspaces and host-authoritative WebRTC sessions use user-relayed signaling via copy/paste, share sheet, or checksummed local QR frames. Guest edits require host commit/ACK; stale edits are retained as local recovery forks. Snapshot replacement cannot modify the design asset manifest; guests must use the verified asset operations. | Mobile browsers without a directory picker cannot use a selected folder as canonical storage. Cursor and remote-selection presence now uses sequenced, bounded protocol-v2 messages relayed by the host; presence stays out of saved designs. There is no automatic merge of conflicting revisions. Validate independent profiles and real devices before release claims. |
| Import and export | Local `.fig` import, SVG, raster exports, and bounded vector PDF are implemented with explicit review/fail-closed behavior. Vector PDF keeps supported user-space alpha and vector masks as bounded soft-mask forms. | `.fig` remains experimental and best effort, with no round-trip guarantee. Vector PDF still refuses text, effects, blend modes, gradient strokes, luminance/object-bounding-box masks, and other unsupported image/vector cases. |
| Saved image recipes (requested extension) | Right-click an edited image to save a recipe, multi-select image layers, apply it in place, and use the progress bar to pause, cancel, retry, and set a worker cap. The bar reports actual render workers plus the shared serialized local-model worker when background removal, expansion, object erase, or resolution boost is part of the recipe; boost reserves up to four CPU slots when cross-origin isolation permits it. Both operations use each target's own source; expansion ratios are source-relative, same-ratio reapplication avoids regenerating borders, and rollback restores the asset, mask, original size, and position. | Finish full lifecycle validation for very large batches, lower-memory phones, cancellation/recovery, and reload/export paths before making a production-scale throughput claim. |

## Verification policy

Node tests and `npm run verify:static` verify local model behavior, worker packaging, and static deployment inputs. They do not prove editor interaction or visual parity. Browser smoke remains deferred until the current feature batch is implemented, as requested; afterward, run the complete browser workflow and focused mobile flows, record failures, and fix them together before release review. Real-device and independent-profile checks remain separate evidence required for mobile persistence, sharing, and performance claims.

The text-on-path distance table is capped at 65,536 samples and is built once per canvas draw, then queried with binary search for each glyph. A local synthetic Node microbenchmark with 400 curved anchors and 156 graphemes measured 28.58–33.18 ms when rebuilding the table per glyph versus 0.23–0.32 ms with one reused table (five paired samples after two warmups; diagnostic only, not a browser or device guarantee).

### Real Pillow-RS batch throughput diagnostic

The reproducible [`pillow-batch-wasm-probe.mjs`](../scripts/research/pillow-batch-wasm-probe.mjs) runs the current Pillow-RS WASM render path in Node worker threads, transfers each original PNG to its worker, reuses `DecodedSourceCache`, encodes the same adjusted PNG previews as the app, and compares SHA-256 output hashes across worker counts. On 2026-10-03, Node 24.18.0 on an Apple M3 Pro (12 logical cores) produced:

| Source dimensions | Images | Requested workers | Active workers after shared render-memory admission | Render rate | Render time | Peak process RSS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1024 × 768 | 24 | 1 | 1 | 4.38 images/s | 5.48 s | 450 MiB |
| 1024 × 768 | 24 | 2 | 2 | 8.29 images/s | 2.90 s | 591 MiB |
| 1024 × 768 | 24 | 4 | 4 | 15.53 images/s | 1.55 s | 692 MiB |
| 1600 × 1200 | 8 | 1 | 1 | 1.71 images/s | 4.69 s | 443 MiB |
| 1600 × 1200 | 8 | 2 | 2 | 3.10 images/s | 2.58 s | 554 MiB |
| 1600 × 1200 | 8 | 4 | 3 | 4.31 images/s | 1.86 s | 620 MiB |

Every output hash matched across worker counts. Four requested workers improved this host's throughput by 3.55× at 1024 × 768 and 2.52× at 1600 × 1200, where the existing 256 MiB active-render budget admitted three concurrent images. The run includes startup separately from the render-rate interval. Peak RSS includes the Node process, all deterministic source fixtures, WebAssembly instances, and outputs; it is not a browser's incremental-worker memory measurement. Node worker threads do not establish Safari/Chrome worker performance or low-memory-phone safety. Use this as evidence that Pillow work benefits from parallel workers on this host, not as a production throughput promise. The browser-worker and representative-device lifecycle gates remain open.
