# Local `.fig` import

Tiny Image Star can import a local Figma Design `.fig` file. Import runs in a dedicated browser worker, on the user's device. It does not call a service. The existing `.flocal` open path is unchanged. The import review shows an explicit loss summary before switching designs, and the accepted design and extracted image assets are saved through the existing local package flow.

This is an **experimental, best-effort import**, not a guarantee of full Figma fidelity or a promise that every `.fig` release will remain readable. `.fig` is a proprietary format that can change; Figma describes saving local copies in its [help documentation](https://help.figma.com/hc/en-us/articles/8403626871063-Save-a-local-copy-of-files). The importer uses the pinned community parser [`openfig-core@0.4.1`](https://github.com/OpenFig-org/openfig-core), not an official Figma implementation or specification.

## Current import surface

The adapter makes frames, groups, sections, rectangles, ellipses, lines, stars, polygons, text, supported Boolean operations, vector paths, and structurally simple vector networks into local editable layers. Simple network blobs retain graph vertices and cubic handles, including multiple one-loop regions; multi-loop holes, styled regions, strokes, and complex graphs remain editable path groups when resolved paths can be preserved. It maps solid paints, ordered linear/radial/angular gradients (including editable linear/radial transforms, stop positions and per-stop alpha), supported embedded raster image fills (including editable local adjustments for seven recognized image filters; the numeric mapping is retained but has not been verified for visual equivalence), CSS-supported layer blend modes, and 16 supported individual fill/stroke paint blend modes, along with basic text settings, page order, visibility, opacity, clipping, constraints, common stroke settings, and common effects. Local component masters and component sets are retained when they can be converted; local instances keep their links and effective layer overrides when descendants can be matched unambiguously by type, name, and order. Variant property definitions, declared options, and member values are imported where all values map to unique local variants. Boolean visibility, text, instance-swap, and slot properties retain their definitions and instance values when the source reference resolves to one compatible local target. Slot content is kept as editable instance children so later component synchronization does not discard it. Nested-instance exposure flags map to the local component's exposed-instance list when the nested instance resolves to a local component; ordinary properties and variant-axis controls appear in the parent Inspector, track supported nested variant swaps, and survive owner-variant mapping and reload. External-library or ambiguous instances remain visually editable as detached layers and appear in import review. Import review also reports property references that target multiple layers, missing or incompatible targets, unknown preferred library assets, slot constraints or preferred values that the local model cannot express, and property types without a local equivalent. Figma `PASS_THROUGH`, `LINEAR_BURN`, `LINEAR_DODGE`, and unknown blend modes are called out in import review and reset to normal. Paint blending under reduced opacity, layer blending, visible effects, masks, or Boolean compositing on the same layer or an ancestor is also called out because the isolated backdrop may render differently locally. Malformed gradients are omitted with import-review warnings; angular gradients retain angle and stops, while off-center angular origins are approximated around the local layer center with a warning. Drop shadows, inner shadows, foreground blur, and background blur remain editable effects; unsupported effect types are omitted, while shadow spread, effect blend mode/order, and values outside local limits are reported as approximations. Text-node fill and stroke stacks remain editable, including supported solid, gradient, and embedded-image fills plus solid and gradient strokes. Supported per-character text styles remain editable rich-text runs, including font family, size, weight, italic, line height, letter spacing, solid color, and underline or strikethrough; style references are validated, missing trailing references inherit the base style, and unsupported range properties or per-character gradient/image paint stacks appear in the import review. Horizontal and vertical Auto Layout frames retain editable direction, gap, padding, wrap, fixed or hug sizing, main/cross-axis alignment, and direct-child absolute, fill, align-self, and min/max sizing where the source exposes those fields. Grid Auto Layout retains ordered tracks, fixed/fill/hug track sizes, row-major or manual cell placement, cell spans and alignment, gaps, padding, and automatic hug rows. Fixed-pixel and content-based minimum grid track bounds are preserved through local layout; unequal flexible minimum/maximum intervals that the local model cannot represent are approximated with the maximum sizing function and reported in the import review. Image sources are checked against the local image engine's dimension ceiling before they enter the design library.

`ALPHA` mask stacks with supported sources and a bounded subset of `VECTOR` mask stacks are imported as editable local mask groups. Vector-mask source coverage uses visible fill and stroke geometry while ignoring paint color, alpha, node opacity, and blend mode, matching the documented Figma distinction. The current vector source subset is simple shapes, paths, and vector networks; lines are stroke-only. Groups, frames, text, images, Boolean layers, auto-layout mask stacks, unsupported sources, and masks with no converted content remain editable as ordinary layers and are called out in import review. `LUMINANCE` masks remain unsupported and are also reported. Sibling order, nested parent boundaries, rotated geometry, and affine transforms are preserved for supported stacks. A `maskType` value without `isMask: true` does not activate masking. Figma defines masks as applying to subsequent siblings and distinguishes `ALPHA`, `VECTOR`, and `LUMINANCE`; see its [isMask property](https://developers.figma.com/docs/plugins/api/properties/nodes-ismask/) and [MaskType definition](https://developers.figma.com/docs/plugins/api/MaskType/).

The importer also flattens unsupported transforms, wrapped-track alignment behavior, and some text/image/stroke settings. Complex or style-overridden Figma vector-network graphs remain visually editable as resolved path layers, but shared graph topology is not retained; oversized node-level fill/stroke geometry blobs are rejected before path decoding. It omits unsupported visible node types, unsupported paints and effects, invalid or oversized vector paths, and missing or unsafe raster sources. An unsupported container with children becomes a local group so its child layers remain editable; supported local effects on that fallback group are retained. The review dialog lists examples and totals; when there are more than 40 examples, it states that the list is truncated.

Import limits are enforced before the synchronous parser runs: 32 MiB archive, 2,048 ZIP entries, 64 MiB expanded data, 32 MiB canvas/message, 1 MiB schema, 250 pages, 25,000 source nodes, and 24 MiB total embedded image data. The worker is terminated after 45 seconds. Unsupported ZIP64/encrypted entries, unsafe names, duplicate paths, integrity failures, malformed frames, and inputs exceeding these limits are rejected. The worker timeout and byte limits bound input work; they are not a strict browser process-memory guarantee.

## Evidence and gaps

The checked-in `circle-v101.fig` and `openfigs-v106.fig` samples come from the OpenFig project's test corpus at a pinned commit, and are retained with the package-declared MIT notice. They demonstrate parser/archive compatibility across versions 101 and 106, but are not official format documentation and do not represent broad production designs. Adapter tests also use synthetic decoded nodes to cover local components, nested instances, effective overrides, variant definitions and values, Boolean/text/instance-swap properties and instance values, custom slot content, and unsupported property-loss reporting; mixed rich-text ranges (including Unicode surrogate pairs and incomplete trailing-zero maps); embedded image fills; per-paint fill/stroke blend-mode mapping and serialization; same-layer and ancestor isolation warnings; alpha-mask stack boundaries and nesting; transformed mask geometry; horizontal and vertical Auto Layout conversion and reflow; manual and row-flow grid conversion; unsupported layers; corrupt archives; resource bounds; parent cycles; and excessive nesting. Renderer and SVG tests verify paint order, backdrop composition, editable serialization, and fail-closed export under isolation boundaries; these are deterministic synthetic tests, not visual parity measurements against Figma.

Before calling this production-ready, add permission-cleared Figma Design exports that include real text, raster fills, mixed text styles, effects, masks, horizontal, vertical, and grid auto-layout, components, and rotated/scaled nested frames. Compare the resulting layers and rendered output on supported mobile browsers and desktop browsers, then revise this support table and limits from measured evidence. The current tests do not establish visual parity for those cases.

## Build and verification

`npm run dev` builds the isolated importer worker before starting the local server. `npm run verify:static` rebuilds that worker and checks that the deployable static tree contains it. The Pages workflow installs from `package-lock.json` and builds the worker in both verification and deployment jobs.

Run `node --test tests/fig-import.test.mjs` for focused import checks, `node scripts/ci-test.mjs` for the full Node test suite, and `npm run verify:static` for deployment-input checks. The browser smoke suite is intentionally not part of this importer change's verification yet.

No `.fig` export, live Figma API access, Figma authentication, `.jam`/`.deck`/`.buzz`/`.site` import, or round-trip preservation is implemented.
