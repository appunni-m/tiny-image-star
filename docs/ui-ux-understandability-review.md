### Understandability verdict

For the concrete question **“How do I crop an image?”**, the UI provides the sequence before the user adds a photo, offers **Add image** as the next step in Help, and repeats the gesture beside the selected photo’s **Crop image** button. The same crop action is available from the image context menu and Inspector. In crop mode, users see the kept area, can adjust its edge handles, and have visible Undo and Finish actions. On phones, **Fit** brings an oversized selection into view first. The path works at both tested sizes; whether unfamiliar users can find and complete it unaided is still unmeasured.

The biggest broad discoverability risk is the editor’s density: the desktop toolbar is icon-led and many advanced properties sit behind sections or modes. The current mitigations are hover/focus tooltips, a selected-tool instruction, touch labels and **More tools**, task search, and contextual actions. Validate those mitigations with observed first-use tasks before claiming the overall editor is easy to learn.

## Direct answer: can a new user figure out how to crop?

There is no separate Crop tool in the bottom strip. Cropping a regular photo is a contextual image action. The start card gives the exact sequence: choose **Add image**, click or tap the photo, choose **Crop image**, drag over the part to keep, then choose **Finish crop**. The Layers empty state cues users to select a photo; Properties explains that selecting an item opens its settings and offers **Add image**. Once a user selects one photo layer, its action bar gives the next steps and the **Crop image**, **Adjust image**, and **Save recipe** actions:

1. Choose **Add image** from the empty Layers or Properties state, or from the empty-canvas start card.
2. Click or tap the photo with the touch-labeled **Select** tool (desktop: **Select / Move**). The image action bar says **Crop image** and explains that dragging selects the area to keep.
3. In crop mode, the on-canvas instructions explain edge/corner adjustment, **Undo crop**, and **Finish crop**. The **Crop shape** menu offers **Free (any shape)**, **Square (1:1)**, **Portrait (4:5)**, **Landscape (3:2)**, and **Widescreen (16:9)**. The chosen ratio constrains both a new drag and edge/corner resizing. Ratios refer to the image as displayed after rotation, while flips only mirror it. The choice lasts for the current editor session and does not change the saved crop representation. A crosshair signals that the canvas is in crop mode.
4. If the user asks **? Help** “How do I crop an image?”, the action search returns the crop flow. If no image is selected, it explains the prerequisite and offers **Add image**.

On a populated page with no selection, Properties now tells the user to select the photo or its containing shape, then look for **Crop image** or **Reposition photo** in the canvas action bar. This puts the selection prerequisite back in view after the empty-page walkthrough has disappeared.

The fresh phone preview showed the empty start card and named touch tools without opening either side panel. Choosing the crop suggestion filled the search with “How do I crop an image?”; **Crop image** was unavailable without a selected photo, and **Add image** was the highlighted next action. For a photo used as a shape fill, select the shape and choose **Reposition photo**; the shape edge is the crop boundary. Drag, pinch, or use Zoom to place the photo inside it. If the fill uses **Fit** or **Tile**, the controls explain that switching to **Fill** lets the photo extend beyond the shape before repositioning. Help still finds this task when the user searches **Crop image inside shape**. When a shape has multiple image fills, the Inspector keeps explicit target controls so the editor does not guess which photo to move.

Focused action-search, image-action, crop-geometry, and mobile-overflow checks verify natural-language crop queries, gesture instructions, photo-fill guidance, ratio-lock geometry through rotations/flips, and mobile control sizing. The fresh preview now confirms that the actual photo crop gesture works on desktop and that **Fit** exposes an offscreen image on narrow phones; none of this proves users understand the controls without help.

## Remaining findings

1. **High — actual task success is unknown.** Focused checks and the synthetic-image walkthrough confirm the crop copy, search, controls, and completion wiring. They do not prove an unfamiliar person will find the contextual image bar or finish cropping without coaching. Observe first actions, completion, wrong turns, and help use before claiming the editor is easy to learn.
2. **Medium — mobile header has source coverage but lacks real-device validation.** Phone widths show compact save status and a direct **Share** action; **File** is still hidden, and export remains inside Properties or Help. Verify the header on narrow portrait and landscape devices, then observe whether people can find sharing and export without coaching.
3. **Medium — crop is contextual, not global.** On a populated page, users must select the photo before **Crop image** appears. When nothing is selected, Properties now points to that action and distinguishes photo layers from photos inside shapes. Crop is also available from the image action bar, context menu, Inspector, and Help. Observe whether users understand the selection prerequisite on desktop and phone before adding another always-visible tool.
4. **Medium — image adjustment vocabulary needs observation.** The Inspector groups crop/transform, light/color, and detail/effects, but terms such as exposure, highlights, and tint may still need examples or simpler descriptions if first-time users cannot predict their result.
5. **Medium — live sharing carries a comprehension cost.** With no server, the guest must return a reply link and the owner must accept it. Verify that users understand who sends each link and when the connection is live.
6. **Medium — mobile recipe-bar coverage is structural, not observational.** The selection step now explains how to select image layers and finish on a phone, but the batch progress bar has not been evaluated during a real multi-image run in portrait and landscape. Check whether progress obscures too much of the work.
7. **Medium — desktop tool recognition depends on icon knowledge or hover.** The toolbar exposes names and gestures through tooltips and task search, while the active-tool status explains the current gesture. Most desktop controls do not keep their names visible. Ask users to find tools such as Text, Comment, Frame, and Pen without pointing at the toolbar; only add persistent labels or reorganize the strip if participants miss them.
8. **Medium — advanced image tools are behind a collapsed group.** Background removal, object erase, subject isolation, Expand, and resolution boost live under **More image tools**. Help suggestions provide another route, but measure whether people locate “remove the background” and “erase an object” without coaching.
9. **Medium — phone overflow and export need direct task checks.** Tool labels are visible on touch, but the 60 px controls overflow and later tools require scrolling or **More tools**. On phones, image export remains in Properties, so selecting artwork and opening the right drawer are prerequisites. Test adding text/comment and exporting an image on portrait and landscape devices.
10. **Medium — Page, frame, and PDF sizes use different mental models.** The editor explains that a Page is an open workspace, a frame sets design dimensions, and PDF export sets paper size, but that explanation is spread across Properties and export. Test “make a 1080 × 1920 design” separately from “export this page for print” and simplify the wording if participants conflate them.
11. **Low — undo is available but not prominent.** Undo and Redo are in File and Help search, while their visible menu shortcuts use Mac symbols on every platform. Check whether people find recovery without knowing shortcuts; show platform-correct hints or persistent controls if they do not.

## What a new user should do to crop

For a regular photo layer: choose **Add image**, click or tap the photo, and choose **Crop image** in its action bar. On a phone, tap **Fit** if the selected image extends beyond the screen. Drag over the area to keep, then adjust an edge or corner if needed. Leave **Crop shape** on **Free (any shape)**, or choose **Square (1:1)**, **Portrait (4:5)**, **Landscape (3:2)**, or **Widescreen (16:9)** before dragging. The same shape is kept when you adjust an edge or corner; it follows the displayed image orientation after rotation. The crop updates when you release; **Finish crop** exits crop mode, and the original remains editable. Use **Undo crop** to reverse the last change.

For a photo inside a shape: select the shape and choose **Reposition photo** from its canvas action bar, then drag the photo within the shape (or pinch/use Zoom on touch) and choose **Done positioning**. The shape edge is the crop boundary. If the fill is set to **Fit** or **Tile**, change it to **Fill** in Design properties first so the photo can extend beyond the shape edge. The **? Help** search finds the task when a user asks **Crop image inside shape**.

The current source communicates these steps. A first-time user study is still needed to answer whether people understand them: give participants only the canvas and the goal “crop this photo to keep the subject,” record their first action and detours, then repeat for the photo-inside-shape case on desktop and phone. Do not coach them or point out **? Help**; discovering it is part of the result.

## Validation still needed

After feature implementation, ask 5–6 people who have not used Tiny Image Star to complete these tasks without coaching: choose a workspace or browser storage, crop a photo layer, crop a photo inside a shape, make a phone-sized frame, save and apply a recipe to several images, export a page PDF, and invite a collaborator. Record their first action, time to start, completion, wrong turns, help searches, and whether they can explain the result. Repeat on a narrow phone viewport. Browser automation can confirm layout and wiring; only observation can confirm whether people understand the interface.
